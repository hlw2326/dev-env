# DevEnv 前端组件化与代码风格规范

**参照：** `zbzs/ele/src/render/src`
**配套：** [命名与精简规范](../../doc/命名与精简规范.md)（命名、禁止兜底）、[FRONTEND_STYLE_GUIDE](../FRONTEND_STYLE_GUIDE.md)（设计令牌、PrimeVue 覆盖）
**优先级：** 与 `FRONTEND_STYLE_GUIDE.md` 冲突时以本文为准，差异见第十四节。

---

## 一、总原则

1. **一个文件一件事。** 页面文件只做编排，区块拆成子组件，状态放 composable，类型放 `types.d.ts`。
2. **读代码像读目录。** 打开 `index.vue` 能一眼看出页面由哪几块组成。
3. **就近放置。** 只有一个页面用的组件、composable 放在该页面目录下，复用达到两处才提升到全局。
4. **注释短而统一。** 每个区块、每个声明上方一行中文短注释，不写长句。
5. **不兜底。** 不写三元，不写 `||` 补默认值，不抄参考项目里的兜底写法（见第十二节）。

│       ├── h-card.vue
│       ├── index.ts
│       └── types.d.ts
├── composables/            # 全局组合式函数，按模块分目录
│   ├── index.ts
│   └── theme/
│       ├── index.ts
│       └── types.d.ts
├── i18n/
├── router/
├── store/                  # 每个模块：index.ts + types.d.ts
├── utils/                  # 按职责分文件，禁止大杂烩
└── views/
    ├── main/               # 主界面外壳（标题栏 + 侧栏 + router-view）
    │   ├── index.vue
    │   ├── comps/          # 外壳私有组件
    │   └── sites/          # 一个页面一个目录

规则：

- 页面目录固定为 `index.vue` + `comps/` + 可选的 `use-xxx.ts`。
- `comps/` 下平铺文件，不再嵌套目录。需要分组时用前缀：`wizard.vue`、`wizard-kind.vue`、`wizard-basic.vue`。
- `App.vue` 只放 `<router-view />`、`<p-toast />`、`<p-confirmdialog />`，不放布局。

## 三、页面拆分规则

### 3.1 什么时候必须拆

- 单个 `.vue` 超过 300 行。
- 模板里出现第二个互不相关的区块：工具栏、列表项、空状态、弹窗、向导步骤、详情页签。
- 一段 `v-for` 内部超过 15 行，拆成列表项组件。
- 一个弹窗或抽屉，拆成独立组件，用 `v-model:visible` 控制。

### 3.2 页面文件长什么样

`index.vue` 只做三件事：引入子组件、持有跨组件共享的状态、把状态通过 props 和 `v-model` 传下去。

```vue
<template>
	<h-page :title="$t('弹幕监控')" :scroll="false" :padding="false">
		<!-- 头部右侧操作 -->
		<template #extra>
			<dm-header />
		</template>

		<!-- 监控主体 -->
		<div class="dm-layout">
			<div class="dm-main">
				<dm-toolbar v-model:filter="filter" v-model:keyword="keyword" />
				<dm-list :messages="messages" />
			</div>
			<dm-side />
		</div>
	</h-page>
</template>

<script setup lang="ts">
import { ref, computed } from 'vue'
import { useDm } from '@/composables'
import DmHeader from './comps/header.vue'
import DmToolbar from './comps/toolbar.vue'
import DmList from './comps/list.vue'
import DmSide from './comps/side.vue'

// 全局弹幕状态
const { list } = useDm()

// 消息类型筛选
const filter = ref('all')
// 搜索关键词
const keyword = ref('')

// 过滤后的消息
const messages = computed(() => filterMessages(list.value, filter.value, keyword.value))
</script>
```

### 3.3 子组件如何拿数据

| 数据 | 做法 |
|---|---|
| 只有父子两层用，且来自父组件 | `props` + `defineModel` |
| 全局数据（列表、配置） | 子组件自己调用 composable，不逐层传递 |
| 只给自己用的临时状态 | 留在子组件内部 |
| 子组件通知父组件 | `defineEmits`，事件名用单个动词：`save`、`close`、`pick` |

双向绑定一律用 `defineModel`，不手写 `modelValue` 加 `update:modelValue`：

```ts
// 双向绑定属性
const filter = defineModel<string>('filter', { default: 'all' })
const keyword = defineModel<string>('keyword', { default: '' })
```

### 3.4 页签页面

页签用一张配置表驱动，内容用异步组件，不写一长串 `v-if`：

```ts
// 页签配置表
const tabs = {
	info: { label: '基本信息', icon: 'pi pi-info-circle', comp: defineAsyncComponent(() => import('./comps/info.vue')) },
	git: { label: 'Git 仓库', icon: 'pi pi-code-branch', comp: defineAsyncComponent(() => import('./comps/git.vue')) },
	conf: { label: 'Nginx 配置', icon: 'pi pi-file-edit', comp: defineAsyncComponent(() => import('./comps/conf.vue')) }
}

// 当前页签
const cur = ref<keyof typeof tabs>('info')
// 当前组件
const active = computed(() => tabs[cur.value].comp)
```

模板里用 `<component :is="active" />`。切换后需要保留内部状态时（比如编辑器内容），改用多个 `v-show`。

### 3.5 卡片式面板

设置类页面由若干 `h-card` 竖向堆叠，一张卡片一个文件，页面文件只负责排列：

```vue
<template>
	<div class="pane">
		<general-basic />
		<general-storage />
	</div>
</template>
```

## 四、全局组件

- 只有两个以上页面用到才放进 `components/`，文件名和目录名用 `h-` 前缀。
- 每个组件目录三件套：`h-xxx.vue`、`index.ts`、`types.d.ts`。简单组件可省 `types.d.ts`，Props 直接写在 `.vue` 里。
- 组件通过 `unplugin-vue-components` 自动注册，页面里不手动 import。
- 插槽命名固定：`title`、`extra`（右上操作区）、`default`。`HPage` 额外有 `header`。
- `defineOptions({ name })` 只用于全局组件，页面和页面子组件不写。

```ts
// components/h-page/index.ts
export { default as HPage } from './h-page.vue'
export type * from './types'
```

```ts
// components/h-page/types.d.ts
export interface HPageProps {
	/** 页面标题 */
	title?: string
	/** 页面描述 */
	desc?: string
	/** 内容间距 */
	padding?: string | number | boolean
}
```

## 五、`<script setup>` 写法

### 5.1 声明顺序

1. `import`（Vue、第三方、`@/` 内部模块、子组件、类型）
2. `defineProps` / `defineModel` / `defineEmits`
3. 调用 composable
4. `ref` / `reactive` 状态
5. `computed`
6. 函数
7. `watch` / 生命周期

不写 `// ===== 区块 =====` 这类分隔线。每个声明上方一行短注释即可。

### 5.2 注释

```ts
// 双向绑定属性
const filter = defineModel<string>('filter', { default: 'all' })

// 统计分类数量
function count(key: string) {
	return list.value.filter((item) => item.type === key).length
}
```

- 中文，一行，说明“这是什么”，不重复代码本身。
- 函数用 `function` 声明，不用 `_` 前缀。
- 模板里每个区块上方也写一行注释：`<!-- 顶部过滤工具 -->`。

### 5.3 Props

一个子组件的 Props 少于 3 个时，直接内联泛型。多了就把接口放进同目录 `types.d.ts`：

```ts
// 组件接收属性
defineProps<{
	messages: Message[]
}>()
```

## 六、Composables

```
composables/
├── index.ts          # export * from './xxx'
└── config/
    ├── index.ts
    └── types.d.ts
```

- 按业务模块分目录，禁止 `useUtils` 这类大杂烩。
- **全局共享状态**写在模块顶层（`const loading = ref(...)` 放在 `useXxx` 外面），所有调用方拿到同一份。
- **每次调用独立的状态**写在 `useXxx` 里面。
- 返回一个扁平对象，状态、计算属性、方法平铺，需要时把 `store` 一起返回。
- 不在 composable 里自动加载数据，由页面在 `onMounted` 里显式调用。
- 只给一个页面用的，放在该页面目录，文件名 `use-xxx.ts`，例如 `views/login/use-captcha.ts`。
- 末尾导出类型：`export type * from './types'`。

```ts
// 系统配置钩子
export function useConfig() {
	// 配置状态仓库
	const store = useConfigStore()
	// 解构状态项
	const { lang, system, update } = storeToRefs(store)

	return { lang, system, update, setLang: store.setLang, store }
}
```

## 七、Store

```
store/
├── index.ts
└── config/
    ├── index.ts
    └── types.d.ts
```

- 初始状态单独定义成 `DEFAULT_CONFIG` 常量，`state` 里展开使用。
- 只持久化用户偏好（语言、主题、窗口设置），列表数据每次从后端取。
- Store 之间不互相引用，需要协调的放到 composable。
- `types.d.ts` 里每个字段上方一行注释。

```ts
// 系统配置
export interface ConfigState {
	// 界面语言
	lang: string
	// 系统设置
	system: SystemConfig
}
```

## 八、API 层

- 一个文件对应一个后端模块：`api/sites.ts`、`api/runtimes.ts`。
- 一个导出函数对应一个后端方法，函数体只调绑定，不做字段映射，不做降级。
- `api/index.ts` 统一 `export *`，页面和 composable 从 `@/api` 引入。
- 页面组件不直接 import `wailsjs`。

```ts
import * as SiteAPI from '../../wailsjs/go/wails/SiteAPI'

// 获取网站列表
export const list = SiteAPI.List

// 获取网站详情
export const get = SiteAPI.Get
```

## 九、类型

- 全局类型放 `types/`，模块类型放各自目录的 `types.d.ts`。
- 优先 `interface`，联合类型才用 `type`。
- 每个字段上方一行注释，或者行尾 `/** */`，二选一，同一个文件保持一致。
- 导出用 `export type * from './types'`。
- 不写 `any`、`as any`。类型来自 `wailsjs/go/models.ts` 时直接引用。

## 十、模板

- 缩进用 Tab，属性超过 3 个换行，一行一个。
- `v-for` 必须带 `:key`，`v-if` 和 `v-for` 不放在同一个标签上。
- 多分支用 `v-if` / `v-else-if` / `v-else`，不用三元。
- 模板里最多一个简单表达式。复杂判断写成 `computed` 或函数。
- 条件类名用对象语法：`:class="{ active: cur === key }"`。
- 状态类名统一：`active`、`fill`、`disabled`。
- 弹窗和抽屉用 `v-model:visible`。

```vue
<!-- 消息主体 -->
<span v-if="msg.type === 'chat'" class="text">{{ msg.content }}</span>
<div v-else-if="msg.type === 'gift'" class="gift">...</div>
<span v-else class="text">{{ $t('进入了直播间') }}</span>
```

## 十一、样式

### 11.1 基本写法

- `<style scoped lang="scss">`，Tab 缩进。
- 嵌套不超过 3 层，用 `&.active`、`&:hover`。
- 类名短而有语义：`.header`、`.body`、`.item`、`.label`、`.desc`、`.actions`。页面前缀只加在根节点：`.dm-layout`。
- 每个区块上方一行注释：`/* 顶部工具栏 */`。
- 长度用 `rem`，1px 边框用 `px`。
- 过渡统一 `transition: all 0.15s ease`。

### 11.2 只用令牌，不写回退值

参考项目写成 `var(--bg-card, #ffffff)`，这里的令牌在 `style.css` 里全局定义，回退值是多余的，也违反“不兜底”：

```scss
// 不要
background-color: var(--bg-card, #ffffff);

// 要
background-color: var(--bg-card);
```

- 颜色只引用令牌：`--bg-app`、`--bg-card`、`--border-color`、`--text-primary`、`--text-secondary`、`--text-muted`、`--p-primary-color`。
- 状态色补进令牌，不在组件里写十六进制：`--ok`、`--warn`、`--err`、`--info`，Light 和 Dark 各定义一份。
- 圆角、间距用 `--h-radius`、`--h-padding`。
- 端口号、PID、路径、命令用 `.font-mono`。
- PrimeVue 的全局外观改动写进 `assets/css/primevue.css`，组件里只在必要时用 `:deep()`。

## 十二、参考项目里不要照抄的部分

参考项目整体结构值得学，下面几处和本项目的“不兜底”原则冲突：

| 参考写法 | 本项目做法 |
|---|---|
| `var(--x, #fff)` 带回退色 | 只写 `var(--x)` |
| `text \|\| $t('默认文案')`、`x \|\| ''` | 数据有就渲染，没有就不渲染，用 `v-if` |
| `settingTabs[cur]?.comp \|\| settingTabs.general.comp` | 页签值由类型约束，直接取 |
| `catch { toast(...) }` 吞掉原因 | 展示后端返回的错误消息 |
| 文件里多余的空行、残留的空 `<style scoped></style>` | 删除 |
| 模板里 `msg.nickname?.[0]` 这类可选链兜底 | Go DTO 保证字段存在，直接取 |

## 十三、i18n

- 中文原文直接作为键：`$t('基本设置')`。
- 不再维护 `zh-CN.ts`。当前语言是中文时 `$t` 直接返回键。
- `en-US.ts` 是一张 `Record<string, string>`，键就是中文原文。
- 带参数用 `{name}` 占位：`$t('确定删除 {name} 吗', { name })`。
- 现有的 `app.title` 这类点分键全部改成中文原文。

## 十四、与 FRONTEND_STYLE_GUIDE.md 的差异

| 项 | 旧文档 | 本文 |

## 十六、自查

提交前逐条过一遍：

- [ ] 页面 `index.vue` 不超过 150 行，任何 `.vue` 不超过 300 行。
- [ ] 页面没有直接 import `wailsjs`。
- [ ] 全局数据由子组件通过 composable 获取，没有逐层传 props。
- [ ] 双向绑定用 `defineModel`。
- [ ] 模板和脚本里没有三元，没有 `|| 默认值`，没有 `as any`。
- [ ] 样式里没有十六进制色值，没有 `var(--x, 回退)`。
- [ ] 每个区块和声明上方都有一行短注释。
- [ ] 没有残留的空样式块、无调用的组件、未使用的 i18n 键。

```bash
# 过长文件
find src -name '*.vue' | xargs wc -l | sort -rn | head
# 三元与兜底
rg ' \? .+ : ' src --glob '*.{ts,vue}'
rg 'var\(--[a-z-]+, ' src
rg 'as any' src
# 构建与类型检查
cd frontend && npm run build
```
