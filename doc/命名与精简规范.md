# DevEnv 命名与精简规范

**适用阶段：** 开发期（未发布）
**目标：** 名字最短、代码最少、没有兜底。有数据就是数据，没有就是空。

---

## 一、总原则

1. **不向下兼容**：不保留旧字段、旧接口、旧表、迁移垫片。要改就直接改，调用方一起改。
2. **不兜底**：不写 `a ? b : c`，不写 `a || b` 补默认值，不写假数据降级。
3. **删冗余**：重复的转换、重复的逻辑、没有调用方的代码，一律删除。
4. **可重构**：为了名字和结构更干净，允许拆文件、拆结构体、改签名。

---

## 二、命名规则

### 2.1 变量、字段、参数

- **能一个单词就一个单词。** 上下文已经说明的前缀、后缀全部去掉。
- 两个单词必须有理由：一个词会和同作用域的另一个名字冲突。
- 三个单词不允许。出现三个单词说明结构拆得不对，先拆结构。
- Go 局部变量用小写单词，TypeScript 用 camelCase 单词，数据库列用 snake_case 单词。
- 方法接收者可以用一个字母（`s`、`r`），这是 Go 惯例。

| 当前 | 目标 | 说明 |
|---|---|---|
| `siteRepo` / `runtimeRepo` / `serviceRepo` | `sites` / `runtimes` / `instances` | 类型已经是 Repository，字段不再重复 |
| `serviceSvc` | `services` | 类型已经是 Service |
| `nginxMgr` / `gitMgr` | `nginx` / `git` | |
| `portChecker` / `publisher` | `probe` / `bus` | 避免和 `ports` 包名冲突 |
| `cleanRoot` / `primaryDomain` | `root` / `domain` | |
| `nginxContent` / `metaBytes` | `conf` / `raw` | |
| `existing` / `item` | `cur` | `site` 是包名，不能当变量 |

### 2.2 领域字段

| 当前 | 目标 |
|---|---|
| `SiteType` | `Kind` |
| `DomainList` | `Domains` |
| `RootPath` | `Root` |
| `RuntimeVersionID` | `RuntimeID` |
| `ServiceInstanceID` | `ServiceID` |
| `GitRemoteURL` / `GitBranch` / `GitLastCommit` / `GitLastPullAt` | `Remote` / `Branch` / `Commit` / `PulledAt` |
| `NginxConfigPath` | `Conf` |
| `ListenPort` / `ProxyTargetPort` | `Port` / `Upstream` |
| `SSLEnabled` / `SSLProvider` / `SSLCertPath` / `SSLKeyPath` | `TLS` / `Issuer` / `Cert` / `Key` |
| `MetadataJSON`（及前端的 `metadata` 副本） | `Meta`（只留一份） |
| `NodeCommand` / `GoExecutable` / `PythonWsgi` | `Cmd`（按 `Kind` 解释） |

字段改名同步到：领域模型、DTO、仓储 SQL、迁移、`wailsjs` 生成物、前端类型。

### 2.3 方法与函数

- 格式 `verbNoun`，即 `xxxXxx`。动词在前，名词在后。
- 只有在两个词表达不清时才允许 `xxxXxxXxxx`，并且要在评审中说明原因。
- 方法挂在哪个类型上，名词就省掉哪个。`SiteService.Create` 优于 `SiteService.CreateSite`。
- 动词统一，不用同义词：

| 动词 | 含义 |
|---|---|
| `list` / `get` | 读多条 / 读一条 |
| `create` / `update` / `delete` | 增 / 改 / 删 |
| `start` / `stop` / `restart` | 进程与站点生命周期 |
| `read` / `write` | 读写文件 |
| `check` | 校验，只返回结果，不改状态 |
| `clone` / `pull` / `push` / `commit` | Git |
| `reload` | 重新加载配置 |

示例：

| 当前 | 目标 |
|---|---|
| `GetSiteNginxConfig` | `Conf`，挂在 `SiteAPI` 上 |
| `SaveSiteNginxConfig` | `SaveConf` |
| `TestSiteNginxConfig` | `CheckConf` |
| `GetSiteLogs` | `Logs` |
| `GetSiteGitStatus` | `GitAPI.Status` |
| `PullSiteGit` / `PushSiteGit` / `CommitSiteGit` | `GitAPI.Pull` / `Push` / `Commit` |

### 2.4 Wails 绑定按模块拆分

现在所有方法都挂在一个 `AppAPI` 上，所以每个方法都得带模块名，名字才不会冲突。改成每个模块一个绑定结构体：

```go
// main.go
Bind: []any{app.Site, app.Git, app.Runtime, app.Service, app.Task, app.Setting}
```

```ts
// frontend/src/api/sites.ts
import { List, Get, Create } from '../../wailsjs/go/wails/SiteAPI'
```

前端 `frontend/src/api/` 仍是唯一封装层（见 CLAUDE.md 第 1 节），页面组件不直接调用绑定。

### 2.5 文件名

- Go 文件一个单词：`git_service.go` 改为 `git.go`，`site_service.go` 改为 `site.go`。
- Vue 页面一个单词：`virtual-hosts.vue` 随虚拟主机模块一起删除，`sites.vue` 取而代之。
- 类型名可以带角色后缀（`SiteService`、`SiteRepository`），领域模型本身用一个词（`Site`）。

## 三、禁止兜底

### 3.1 不写三元，不补默认值

以下写法全部禁止：

```ts
s.gitBranch || 'main'                 // 读时补默认值
input.rootPath ?? ''                  // 空合并补值
siteType === 'go' ? 8080 : 3000       // 三元
```

```go
if input.StartCommand != "" { cmd = input.StartCommand } else { cmd = "npm start" }
```

替代做法：

- **读取时不补值。** 数据库有什么就返回什么，空串、`0`、`false`、空切片就是“没有”。
- **默认值只在写入入口出现一次。** 来源只有两个：表单初始值，或迁移里的列 `DEFAULT`。
- **按类型区分的预设放一张表**，创建时查一次：

```go
var preset = map[Kind]Preset{
    Node: {Port: 3000, Cmd: "npm start"},
    Go:   {Port: 8080, Cmd: "./main.exe"},
}
```

- **Go 返回的切片不能是 nil。** 在 DTO 转换处统一 `make([]T, 0)`，前端不再写 `|| []`。
- **模板里用 `v-if` / `v-else`**，不用三元表达式。
- **输入不合法就拒绝，不替用户改。** 校验失败返回 `INVALID_ARGUMENT`，不静默修正。

### 3.2 不要假数据，不要前端降级

`frontend/src/api/sites.ts` 里约一半代码是 `isWailsAvailable()` 之后的 localStorage 模拟分支。全部删除：

- 删除 `isWailsAvailable`、`getFallbackSites`、`saveFallbackSites`、`SITES_STORAGE_KEY`，以及每个函数里的降级分支。
- 删除 `mapDTOToSite`。`wailsjs/go/models.ts` 已有类型，Go 的 DTO 保证字段齐全，前端直接用。
- 删除 `generatePreviewNginxConfig`。它在重复实现 Go 的 `GenerateConfig`，预览改调后端。
- `GetSiteLogs` 现在返回伪造日志。改为读取真实日志文件的末尾 N 行，文件不存在返回空切片。
- 前端不再能脱离 Wails 单独运行，调试一律用 `wails dev`（浏览器访问 `http://localhost:34115`）。

### 3.3 不吞错误

- `_ = ...`、`x, _ := ...` 不允许用来掩盖失败。错误要么返回，要么记录日志后明确继续。
- 例：`CreateSite` 里 Git 克隆失败后 `os.MkdirAll` 兜底，改为直接返回克隆错误。
- 例：`GetByDomain` 的错误被丢弃，改为判断 `err`，再判断是否存在。
- 例：`json.Unmarshal` 失败被忽略，改为返回错误。

## 四、要删的冗余

| 位置 | 处理 |
|---|---|
| `SiteService.MigrateLegacyData` | 删除。开发期不迁移旧数据 |
| 旧的项目管理、虚拟主机的服务、仓储、DTO、页面、路由 | 网站模块替代后整体删除（见《网站管理模块设计》） |
| `if s.publisher != nil` 守卫 | 删除。`bus` 由构造函数注入，必然存在 |
| 配置历史“头插加截断到 15 条”的重复代码（`Update`、`SaveNginxConfig`） | 合并为一个方法 `push` |
| `metadataJson` 和 `metadata` 两份 | 只保留 `meta`，由后端序列化 |
| `as any` 强转 | 删除，类型对齐即可 |
| 没有调用方的导出函数、类型、i18n 键 | 删除 |

## 五、数据库

- 表名前缀 `system_`、自增 `INTEGER` 主键、RFC 3339 时间，保持 CLAUDE.md 第 2 节不变。
- 列名随字段一起改成单词（`root`、`port`、`kind`、`meta`）。
- **开发期例外：** 不再追加迁移文件，直接修改 `001` 迁移，然后删除本地 `%LOCALAPPDATA%/DevEnv/data/devenv.db` 重建。首次发布前冻结迁移，从那之后恢复“只追加、不修改”。

---

## 六、落地顺序

1. 先删：旧项目管理、虚拟主机、`MigrateLegacyData`、前端降级分支。
2. 再改名：领域模型、迁移、仓储 SQL、DTO，然后重新生成 `wailsjs`。
3. 拆绑定：`AppAPI` 拆成 `SiteAPI`、`GitAPI` 等，更新 `main.go` 和 `frontend/src/api/`。
4. 去兜底：按第三节逐文件清理，默认值收敛到表单初始值和 `preset`。
5. 更新 `README.md`（前端单独调试一节）和 `CLAUDE.md`（迁移例外）。

## 七、自查命令

```bash
# 三元与兜底（结果应为 0）
rg ' \? .+ : ' frontend/src --glob '*.{ts,vue}'
rg "\|\| ('|\"|\[|\{|[0-9])" frontend/src
# 吞错误（逐条确认）
rg '_ = |, _ :?= ' internal
# 过长的名字（三个单词以上的 camelCase 标识符）
rg '\b[a-z]+[A-Z][a-z]+[A-Z][a-z]+[A-Z]' internal frontend/src
# 构建与测试
go build ./... && go test ./...
cd frontend && npm run build
```
