# 服务实例自动创建与版本切换设计

**目标：** 去掉「运行环境 → 创建服务」这一步。软件商店安装完成后自动生成服务实例，用户只在「服务实例」页启动、停止、切换版本。

---

## 一、问题与现状

### 1.1 现有流程

```
软件商店安装 → 运行环境页点【创建服务】 → 服务实例页 → 启动
```

多出来的一步就是【创建服务】，而且它目前不可用。

### 1.2 「创建服务」无效的原因

| # | 现象 | 代码位置 |
|---|------|----------|
| 1 | 按钮只做路由跳转 `/services?runtimeId=..&runtimeType=..`，服务页从不读取这两个参数，也没有创建表单 | `frontend/src/views/main/runtimes/use-runtimes.ts` 的 `goService` |
| 2 | 后端 `ServiceAPI` 没有 `Create`，服务实例只有两个来源：首次启动时 `seedServices`（只给第一个 PHP 建一条，且仅当服务表为空），以及建站向导的 `AutoService` | `internal/app/bootstrap.go`、`internal/app/site.go` |
| 3 | Nginx、MySQL、Redis 等非 PHP 运行环境只存在浏览器 localStorage，ID 是 `1000 + Date.now() % 100000` 的伪 ID，`system_runtime_versions` 里没有记录 | `frontend/src/api/runtimes.ts` |
| 4 | `system_service_instances.runtime_id` 是指向 `system_runtime_versions` 的外键，所以即使补上 Create，Nginx 的伪 ID 也会触发外键错误 | `migrations/000001_init.sql` |
| 5 | `installPackage` 只把路径登记一下，并没有下载和解压 | `frontend/src/api/store.ts` |
| 6 | `RuntimeService.List/Register/SetDefault` 全部写死 `TypePHP` | `internal/app/runtime.go` |
| 7 | `buildSpec` 只支持 php、nginx、mysql、redis，postgresql 和 apache 会返回「不支持的服务类型」 | `internal/app/service.go` |

结论：第 1、2 条是直接原因。第 3 到 6 条说明非 PHP 环境从安装到入库这条链路本身没打通，这是本方案的前置条件（见阶段 0）。

## 二、目标设计

### 2.1 核心规则

1. **运行环境页只管安装与卸载**，不再出现【创建服务】、【初始化实例】等跳转按钮。
2. **安装成功即确保服务实例存在**：该服务类型下还没有任何实例时，自动创建一条并指向刚装的版本。
3. **同类型再装别的版本不新建实例**，只是多一个可选版本，在服务页切换。
4. **服务页是唯一的启停和选版本入口**：启动、停止、重启、查看日志、切换版本。
5. **版本切换要求实例已停止**。正在运行时由前端提示「将先停止、切换后再启动」，后端同样校验。

### 2.2 自动创建的默认值

| 类型 | 实例名 | 默认端口 | 说明 |
|------|--------|----------|------|
| php | `PHP FastCGI` | 9000 | 沿用现有 `buildSpec` |
| nginx | `Nginx` | 80 | `buildSpec` 当前不传端口，端口来自 nginx.conf，这里仅作展示与占用检测 |
| mysql | `MySQL` | 3306 | 数据目录为空时需先初始化，见 2.4 |
| redis | `Redis` | 6379 | |

端口选择：从默认端口开始，用 `PortChecker.IsPortAvailable` 探测，被占用则顺延到下一个可用端口，结果写入实例的 `port`。`AutoStart` 默认为 `false`，`Enabled` 为 `true`。

postgresql 和 apache 在 `buildSpec` 支持之前不自动创建实例，否则会生成一个永远启动不了的实例。

### 2.3 是否安装后立即启动

建议：**创建实例后尝试启动 php、nginx、redis，启动失败只提示，不让安装失败**。mysql 不自动启动，等初始化完成。这一项见第六节待确认。

### 2.4 MySQL 初始化并入首次启动

现有设计里 MySQL 有单独的【初始化实例】按钮。改为：首次启动时若数据目录不存在或为空，先执行 `mysqld --initialize-insecure --datadir=<dataPath>`，再启动。数据目录放在 DevEnv 自己的 `data/mysql/` 下，与用户项目数据严格隔离（符合 CLAUDE.md 第 1.3 条）。这一步放到阶段 3，不阻塞前两个阶段。

### 2.5 卸载规则调整

自动创建的实例会引用运行环境，如果沿用现在「有服务引用就禁止卸载」，用户永远卸不掉第一个版本。新规则：

1. 被网站引用（`system_sites.service_id` 指向该实例）：禁止，提示先解绑。
2. 实例正在运行：禁止，提示先停止。
3. 同类型还有其他已安装版本：提示先在服务页把实例切换到别的版本。
4. 这是同类型最后一个版本，且实例已停止、无网站引用：卸载时连同实例一起删除。

删除实例只删元数据，不动数据目录（符合「严禁静默递归删除用户目录」）。

## 三、后端设计

### 3.1 分层与依赖

```
transport/wails   RuntimeAPI.Install / ServiceAPI.SwitchRuntime
        │
app               RuntimeService ──► ports.ServiceProvisioner ◄── ServiceService
        │
ports             ServiceProvisioner（新增，接口放在使用方一侧）
domain            service.Instance、runtime.RuntimeVersion（不变）
infra             sqlite 仓库、process、network（不变）
```

`RuntimeService` 要在安装后创建实例，`ServiceService` 又依赖运行时仓库，直接互相持有会形成循环依赖。做法是在 `internal/ports/` 新增一个很小的接口，由 `ServiceService` 实现，`RuntimeService` 只依赖接口：

```go
// internal/ports/service_provisioner.go
type ServiceProvisioner interface {
	// EnsureForRuntime 保证该运行环境类型下至少有一个服务实例，已有则原样返回
	EnsureForRuntime(ctx context.Context, rt runtime.RuntimeVersion) (*service.Instance, bool, error)
	// OnRuntimeRemoved 运行环境被卸载时清理孤立的服务实例
	OnRuntimeRemoved(ctx context.Context, rt runtime.RuntimeVersion) error
}
```

### 3.2 ServiceService 新增方法

```go
func (s *ServiceService) EnsureForRuntime(ctx, rt) (*service.Instance, bool, error)
func (s *ServiceService) SwitchRuntime(ctx, id, runtimeID int64) error
func (s *ServiceService) OnRuntimeRemoved(ctx, rt) error
func (s *ServiceService) Reconcile(ctx) error
```

`EnsureForRuntime`：

1. 不支持自动创建的类型（postgresql、apache）直接返回 `nil, false, nil`。
2. `instances.ListByType(rt.RuntimeType)` 非空则返回已有实例，`created=false`。
3. 按 2.2 的默认值挑端口，创建实例，`created=true`。
4. 发布 `service:created` 事件。

`SwitchRuntime`：

1. 读取实例与目标运行环境，两者类型必须一致，否则 `INVALID_ARGUMENT`。
2. 实例状态为 running 或 starting 时返回 `SERVICE_RUNNING`。
3. 目标运行环境状态必须是 installed，否则 `INVALID_ARGUMENT`。
4. 更新 `runtime_id`，`ConfigPath` 如果指向旧版本目录则置空。
5. 发布 `service:updated` 事件。

`Reconcile` 替换现有的 `seedServices`：遍历所有运行环境类型，对「有运行环境但没有实例」的类型调用 `EnsureForRuntime`。幂等，应用每次启动都跑，同时修复老用户已安装环境却没有实例的情况。

### 3.3 RuntimeService 改动

| 方法 | 改动 |
|------|------|
| `List` | 去掉 `TypePHP` 硬编码，返回全部类型，`PHPVersionView` 更名为 `RuntimeView` 并带上 `runtimeType`；PHP 专属字段（默认 CLI）保留 |
| `Register` | 增加 `runtimeType` 参数，写入数据库而不是前端 localStorage |
| `Install`（新增） | 下载、校验、解压、`Register`、`provisioner.EnsureForRuntime`，通过任务系统上报 `task:progress` 与 `task:completed` |
| `Delete` | 先按 2.5 校验，再删记录，最后 `provisioner.OnRuntimeRemoved` |
| `Scan` | 仍只扫描设置里的运行环境根目录，不再写死 `C:\php`、`D:\php` |

`Install` 返回 `InstallResult{ RuntimeID, ServiceID *int64, ServiceCreated bool }`，前端据此提示。

### 3.4 数据库

不需要新表。区分「自动创建」与「用户手建」只在卸载时用到，且现在没有用户手建入口，所以先不加列。如果后面开放手动新建实例，再在 `000001_init.sql` 里给 `system_service_instances` 加 `managed INTEGER NOT NULL DEFAULT 1`（开发阶段允许直接改初始脚本，见 CLAUDE.md 第 2.4 条）。

### 3.5 错误码与事件

| 类型 | 名称 | 用途 |
|------|------|------|
| 错误码（复用，已在 `errors.go` 中） | `SERVICE_RUNNING` | 切换版本或卸载时实例仍在运行 |
| 错误码（复用） | `INVALID_ARGUMENT`、`NOT_FOUND`、`PORT_ALREADY_IN_USE` | 类型不匹配、实例不存在、端口占用 |
| 事件（新增） | `service:created`、`service:updated` | 服务页自动刷新 |
| 事件（沿用） | `task:progress`、`task:completed`、`service:status-changed` | 安装进度与状态变化 |

### 3.6 Wails 绑定

```go
// RuntimeAPI
Install(in dto.InstallRuntimeInput) (dto.InstallResultDTO, error)

// ServiceAPI
SwitchRuntime(in dto.SwitchRuntimeInput) (dto.OperationResultDTO, error)
RuntimeOptions(id int64) ([]dto.RuntimeOptionDTO, error) // 同类型可选版本
```

`ServiceInstanceDTO` 增加 `runtimeVersion` 与 `runtimePath`，服务页卡片直接展示，不用再拿 `runtimeId` 去反查。

绑定层只做 DTO 转换，不写业务逻辑。

## 四、前端设计

### 4.1 运行环境页

文件：`frontend/src/views/main/runtimes/`

- `comps/card.vue`：删除所有【创建服务】、【初始化实例】按钮。PHP 保留【配置扩展】【设为默认】，Nginx 和 Redis 保留【测试配置】【测试连接】，通用的【卸载】保留。
- 卡片的引用统计改成「被 N 个网站使用」，并加一个状态徽标：该版本是某个服务实例当前使用的版本时显示「服务使用中」，点击跳转 `/services`。
- `use-runtimes.ts`：删除 `goService`、`initDb`，以及 `index.vue`、`comps/group.vue` 里对应的事件透传。
- 卸载弹窗根据 2.5 的规则展示具体阻塞原因，而不是笼统的「被服务引用」。

### 4.2 软件商店

文件：`frontend/src/views/main/store/use-store.ts`、`frontend/src/api/store.ts`

- `installPackage` 改为调用 `RuntimeAPI.Install`，不再走 `registerRuntime` 的 localStorage 分支。
- 进度条改用后端 `task:progress` 事件，替换现在的假进度定时器。
- 安装成功提示根据 `serviceCreated` 区分：
  - 新建了实例：「Nginx 1.26.3 安装成功，已创建服务实例」，附【前往服务实例】链接。
  - 未新建：「PHP 8.2.34 安装成功，可在服务实例中切换到此版本」。

### 4.3 服务实例页

文件：`frontend/src/views/main/services/`

卡片 `comps/card.vue` 增加版本下拉：

```
┌──────────────────────────────────────────┐
│ Nginx                       ● 运行中      │
│ 版本  [ 1.26.3  ▾ ]   端口 80   PID 12345 │
│ [停止] [重启] [日志]                [删除] │
└──────────────────────────────────────────┘
```

- 下拉选项来自 `ServiceAPI.RuntimeOptions(id)`，只列同类型已安装版本。
- 只有一个可选版本时下拉禁用，并附提示「在软件商店安装更多版本」。
- 选择其他版本：
  - 实例已停止：直接调用 `SwitchRuntime`。
  - 实例运行中：弹确认框「将先停止服务，切换后重新启动」，确认后依次 `Stop`、`SwitchRuntime`、`Start`。重新启动失败时保持新版本、状态置为 failed，并提示日志入口，不自动回滚。
- 监听 `service:created`、`service:updated`、`service:status-changed` 自动刷新列表。
- 空状态文案改为「暂无服务实例，请先在软件商店安装运行环境」，并给一个跳转商店的按钮。
- `use-services.ts` 新增 `switchRuntime`，所有 Wails 调用统一经 `frontend/src/api/services.ts` 封装，不在组件里直接调绑定。

### 4.4 API 封装清理

`frontend/src/api/runtimes.ts` 里的 localStorage 逻辑（`getStoredRuntimes`、`saveRuntimes`、非 PHP 分支）在阶段 0 完成后整体删除，`listAllRuntimes` 直接返回后端列表。

## 五、实施步骤

### 阶段 0：打通非 PHP 运行环境（前置，体量最大）

1. `RuntimeService.List/Register` 去掉 PHP 硬编码，支持全部类型。
2. 实现真实的下载、校验、解压（`ports` 里已有下载器契约的话复用，没有就在 `infra` 新增）。
3. `RuntimeAPI.Install` 接入任务系统与事件。
4. 前端删除 localStorage 分支。
5. 迁移处理：浏览器里 `devenv_custom_runtimes` 的旧数据，首次启动时让用户重新通过【扫描】登记，或在前端读取后调 `Register` 一次性写入数据库再清掉 key。伪 ID 不能直接沿用。

### 阶段 1：自动创建服务实例

1. 新增 `ports.ServiceProvisioner`，`ServiceService` 实现 `EnsureForRuntime`、`Reconcile`。
2. `bootstrap.go` 用 `Reconcile` 替换 `seedServices`。
3. `RuntimeService.Install` 与 `Register` 成功后调用 `EnsureForRuntime`。
4. 前端删除【创建服务】入口，商店安装后的提示文案。

阶段 1 完成后，用户的路径已经是「安装 → 服务页启动」。

### 阶段 2：版本切换与卸载规则

1. `ServiceService.SwitchRuntime`、`RuntimeOptions`，运行中拒绝切换时使用已有的 `SERVICE_RUNNING`。
2. 服务页卡片版本下拉与确认流程。
3. `RuntimeService.Delete` 按 2.5 重写，`OnRuntimeRemoved` 清理孤立实例。

### 阶段 3：补齐

1. MySQL 首次启动自动初始化数据目录。
2. `buildSpec` 补 postgresql 和 apache，随后放开它们的自动创建。
3. 服务页配置端口的编辑入口。

### 测试

| 层 | 用例 |
|----|------|
| `app` | `EnsureForRuntime`：首次创建、重复调用幂等、端口被占用时顺延、postgresql 不创建 |
| `app` | `SwitchRuntime`：类型不匹配、实例运行中、目标未安装、成功切换 |
| `app` | `Delete`：被网站引用、实例运行中、最后一个版本连带删除实例、仍有其他版本时拒绝 |
| `app` | `Reconcile`：多次执行不产生重复实例 |
| `sqlite` | 外键 `runtime_id ON DELETE RESTRICT` 在先删实例后删运行环境的顺序下可通过 |

现有 `internal/app/site_test.go` 与 `repositories/repo_test.go` 的风格可直接沿用。

## 六、待确认

1. **安装后是否自动启动？** 方案默认对 php、nginx、redis 尝试启动，失败只提示。如果你希望完全手动启动，去掉即可。
2. **PHP 多版本是否要同时运行？** 方案默认「每个类型一个实例，切换版本」。如果你需要 PHP 8.3 和 7.4 同时跑（各自端口、不同站点绑定不同版本），PHP 应改为每个已安装版本一个实例、端口依次 9000、9001……，这会让 `EnsureForRuntime` 对 PHP 走「每个运行环境一个实例」分支。这与你说的「选择版本」不完全一致，所以需要你定。
3. **阶段 0 是否接受？** 它比「去掉创建服务」大很多，但不做的话非 PHP 的自动创建没法落地。如果下载安装另有计划，请告诉我，我只做阶段 1 到 2 里 PHP 能走通的部分。
4. **旧的 localStorage 数据** 怎么处理：重新扫描登记，还是一次性迁移。


1：安装后自动
2：php多个版本，是切换版本，不同站点可以选择不同的php版本
3：接受去掉创建服务
4，旧的localStorage数据可以全部删除， 现在在开发阶段，随便删除修改
