# 数据库

SQLite,位置 `%LOCALAPPDATA%\DevEnv\data\devenv.db`。迁移逻辑集中在 `internal/infra/sqlite/`,业务层不感知。

## 一、约定

- 表名 `system_` 前缀,主键 `INTEGER PRIMARY KEY AUTOINCREMENT`(Go `int64`,TS `number`)。
- 时间为 UTC RFC 3339 字符串,列名 `created` `updated`。
- 连接统一开启外键、WAL、`busy_timeout`。
- 列名用单个完整单词(见 [命名.md](命名.md))。
- 建表语句不写 `IF NOT EXISTS`。表已存在说明库被外部改过,应该报错而不是被掩盖。
- 不写 `PRAGMA foreign_keys`,连接层已统一开启,事务内切换无效。
- 站点不存运行状态,运行状态由网关与进程管理器实时给出。

## 二、表

| 表 | 说明 |
|----|------|
| `system_software` | 已安装软件,一行一个版本。`UNIQUE (kind, version)`,索引 `(kind, state)` |
| `system_sites` | 网站。`software` 外键 `ON DELETE RESTRICT` |
| `system_site_domains` | 站点域名。`UNIQUE (host)`,`site` 外键 `ON DELETE CASCADE` |
| `system_app_settings` | 键值设置,键只有 `theme` `root` `port` `hosts` |
| `system_schema_migrations` | 迁移记录,由 Go 代码创建,不放进迁移文件 |

- 域名唯一性由数据库保证,不靠应用层先查后写。
- 设置的默认值由迁移脚本建库时一次性写入,读取时不再补默认。
- 有站点绑定某软件版本时不能卸载,`RESTRICT` 报错,不静默置空。

## 三、迁移文件

位置 `internal/infra/sqlite/migrations/`,`go:embed` 打包。

```
000001_init.sql          建全部业务表和索引
000002_seed_settings.sql 初始数据,需要时才建
```

- 文件名 `{6位序号}_{snake_case说明}.sql`,序号全局唯一、严格递增。
- 文件名不合法、序号重复:启动报错,**不跳过**。
- 一个文件一个事务,任一语句失败整体回滚,该版本不入记录表。
- 建表文件只放 DDL,初始数据单独成文件,只放 `INSERT`。
- UTF-8 无 BOM,注释用 `--`。

迁移记录表:

```sql
CREATE TABLE system_schema_migrations (
    version     INTEGER PRIMARY KEY,
    name        TEXT    NOT NULL,
    checksum    TEXT    NOT NULL,
    started_at  TEXT    NOT NULL,
    finished_at TEXT    NOT NULL
);
```

`checksum` 是文件内容 SHA-256,换行统一成 `\n` 后再算。

## 四、开发阶段规则

1. 直接改 `000001_init.sql`,不新增 `ALTER TABLE` 迁移。
2. 改表必须同步改全链路(第六节),不允许"表已改、代码还在读旧列"。
3. 不写兼容:不保留废弃列,不探测旧库,不在读取时兜底旧格式。
4. 库与脚本不一致时启动报错,由开发者显式重置。

## 五、启动流程与漂移

`sqlite.Open(path, opts)`:

1. 创建数据目录,打开连接。
2. 创建 `system_schema_migrations`(如不存在)。
3. 读取并校验内嵌迁移文件:文件名格式、序号唯一。
4. 与已记录迁移逐项核对,出现以下任一项即**漂移**:
   - 记录里有、文件里没有。
   - 记录与文件的 checksum 不同。
   - 文件序号小于已记录最大序号且未记录。
5. 有漂移:`ResetOnDrift=false` 返回 `SchemaDriftError` 并列出每项差异,启动终止;`ResetOnDrift=true` 备份、删库、重建。
6. 无漂移有待执行迁移:库非空先备份(`pre-migrate`),按序号升序逐个执行。
7. 完成后执行 `PRAGMA foreign_key_check`,有结果即报错。

- 重置开关是环境变量 `DEVENV_DB_RESET=1`,由 `internal/app/bootstrap.go` 读取并传入。`sqlite` 包不读环境变量。
- 只有出现漂移才重置。库与脚本一致时设了变量也不动库。
- 重置动作:`VACUUM INTO` 备份 → 关闭连接 → 删 `devenv.db` `-wal` `-shm` → 重建。备份失败则中止。
- 迁移执行器接收 `fs.FS`,测试用 `fstest.MapFS` 构造迁移集合。

## 备份

目录 `%LOCALAPPDATA%\DevEnv\data\backups\`,命名 `devenv-{yyyyMMddHHmmss}-{reason}.db`,`reason` 为 `pre-migrate` 或 `pre-reset`。用 `VACUUM INTO`,保留最近 5 份。空库首次初始化不备份。

## 六、改表同步清单

同一次提交里改完:

| 层 | 位置 |
|----|------|
| 迁移脚本 | `internal/infra/sqlite/migrations/000001_init.sql` |
| 仓库实现与测试 | `internal/infra/sqlite/repositories/` 的 `INSERT` `SELECT` `UPDATE` 与 `Scan` 顺序 |
| 领域模型 | `internal/domain/*/` 字段与 json tag |
| 端口契约 | `internal/ports/` 方法签名 |
| 应用服务 | `internal/app/` |
| 传输层 | `internal/transport/wails/` 的 DTO 与转换 |
| Wails 生成物 | `frontend/wailsjs/go/models.ts`,用 `wails generate module` 重新生成 |
| 前端 | `frontend/src/types/index.ts`、`api/`、`views/` |

改完至少执行 `go build ./...`、`go test ./...`、`cd frontend && npx vue-tsc --noEmit`。

## 七、发布后

首次发布后规则反过来:

1. 已发布的迁移文件冻结,改了就报漂移,发布版不提供重置开关。
2. 结构变更只能新增迁移文件,如 `000003_add_xxx.sql`。
3. 不写回滚迁移,要撤销就再新增一个反向迁移。
4. 删列、改列走重建流程:建新表、拷数据、删旧表、改名,写在一个迁移里。
5. 测试里固化已发布迁移的 checksum 清单。

切换那天:确定最终的 `000001_init.sql`,生成 checksum 清单,移除 `DEVENV_DB_RESET`。
