# 前端

技术栈:Vue 3 `<script setup>` + TypeScript + PrimeVue + Pinia + Vue Router(Hash 模式)+ Vite。自动导入由 `unplugin-auto-import` 与 `unplugin-vue-components` 提供。没有 i18n,界面只有中文,文案直接写中文。

## 一、目录

```
src/
├── api/          一个文件对应一个后端模块:sites software system win
├── assets/css/   style.css(令牌)  primevue.css(覆盖)
├── bootstrap/    启动引导
├── components/   全局组件,h- 前缀,两个以上页面复用才放这里
├── composables/  全局组合式函数,按模块分目录
├── router/
├── store/        仅主题等用户偏好
├── types/
├── utils/        按职责分文件,禁止大杂烩
└── views/main/
    ├── index.vue        外壳:标题栏 + 侧栏 + router-view
    ├── comps/           外壳私有组件
    └── <page>/          index.vue  use-xxx.ts  comps/
```

- 页面目录固定为 `index.vue` + `comps/` + 可选的 `use-xxx.ts`。
- `comps/` 平铺,不嵌套。分组用前缀:`detail.vue` `detail-overview.vue`。
- `comps/` 里的文件不带前缀(`demo.vue`),使用处标签写 `<comp-demo />`,import 名 `CompDemo`。详见 [命名.md](命名.md) 第六节。
- 只有一个页面用的组件、composable 放该页面目录,复用到两处才提升到全局。
- `App.vue` 只放 `<router-view />`、`<p-toast />`、`<p-confirmdialog />`。
- 全局组件目录三件套:`h-xxx.vue` `index.ts` `types.d.ts`。简单组件可省 `types.d.ts`。

## 二、拆分

必须拆:

- 单个 `.vue` 超过 300 行。
- 模板里出现第二个互不相关的区块:工具栏、列表项、空状态、弹窗、详情页签。
- `v-for` 内部超过 15 行。
- 弹窗和抽屉,用 `v-model:visible` 控制。

`index.vue` 只做三件事:引入子组件、持有跨组件共享状态、通过 props 和 `v-model` 传下去。不超过 150 行。

## 三、数据流

| 数据 | 做法 |
|------|------|
| 父子两层、来自父组件 | `props` + `defineModel` |
| 全局数据 | 子组件自己调 composable,不逐层传 |
| 自己用的临时状态 | 留在子组件内 |
| 通知父组件 | `defineEmits`,事件名用单个动词:`save` `close` `pick` |

- 双向绑定一律 `defineModel`,不手写 `modelValue` 加 `update:modelValue`。
- 页签用配置表加异步组件,不写一长串 `v-if`;需要保留内部状态时改用 `v-show`。
- 设置类页面由若干 `h-card` 竖向堆叠,一张卡片一个文件。

## 四、`<script setup>`

声明顺序:

1. `import`(Vue、第三方、`@/` 内部、子组件、类型)
2. `defineProps` `defineModel` `defineEmits`
3. 调用 composable
4. `ref` `reactive`
5. `computed`
6. 函数
7. `watch` 与生命周期

- 函数用 `function` 声明,不用 `_` 前缀。
- 不写 `// ===== 区块 =====` 分隔线。
- 每个声明上方一行中文短注释,说明"这是什么",不重复代码。模板区块上方写 `<!-- 顶部工具栏 -->`。
- 少于 3 个 Props 直接内联泛型;多了放同目录 `types.d.ts`。
- `defineOptions({ name })` 只用于全局组件。
- 不用 `withDefaults` 补值;能由类型约束就不补。

## 五、Composable

- 按业务模块分目录,禁止 `useUtils`。
- 全局共享状态写在模块顶层,所有调用方拿同一份;每次调用独立的状态写在 `useXxx` 里。
- 返回扁平对象,状态、计算属性、方法平铺。
- 不在 composable 里自动加载数据,由页面 `onMounted` 显式调用。
- 只给一个页面用的放页面目录,文件名 `use-xxx.ts`。

## 六、Store

- 只持久化用户偏好(主题),列表数据每次从后端取。
- Store 之间不互相引用,需要协调的放 composable。
- 初始状态单独定义成常量。

## 七、API 层

- 一个导出函数对应一个后端方法,函数体只调绑定。
- 不做字段映射,不做降级,不写 `isWailsAvailable` 或 localStorage 模拟。
- `api/index.ts` 统一 `export *`,页面从 `@/api` 引入。
- 页面组件不直接 import `wailsjs`。
- 前端不能脱离 Wails 单独运行,调试用 `wails dev`(浏览器访问 `http://localhost:34115`)。

```ts
import * as SiteAPI from '../../wailsjs/go/wails/SiteAPI'

// 获取网站列表
export const list = SiteAPI.List
```

## 八、类型

- 类型来自 `wailsjs/go/models.ts` 时直接引用,不再手写一份。
- 优先 `interface`,联合类型才用 `type`。
- 不写 `any`、`as any`。
- 每个字段上方一行注释,同一文件保持一致。
- 导出用 `export type * from './types'`。

## 九、模板

- Tab 缩进;属性超过 3 个换行,一行一个。
- `v-for` 必须带 `:key`;`v-if` 与 `v-for` 不放同一标签。
- 多分支用 `v-if` / `v-else-if` / `v-else`,不用三元。
- 模板里最多一个简单表达式,复杂判断写成 `computed` 或函数。
- 条件类名用对象语法:`:class="{ active: cur === key }"`。状态类名统一:`active` `fill` `disabled`。
- 端口号、PID、路径、命令用 `.font-mono`。

## 十、依赖

只保留 Vue、Vue Router、Pinia、PrimeVue、primeicons 及构建插件。没有引用的依赖从 `package.json` 移除。

## 自查

```bash
# 过长文件
find frontend/src -name '*.vue' | xargs wc -l | sort -rn | head
# 页面直接碰绑定
rg 'wailsjs' frontend/src/views
rg 'as any' frontend/src
# 构建与类型检查
cd frontend && npx vue-tsc --noEmit && npm run build
```

- [ ] 任何 `.vue` 不超过 300 行,`index.vue` 不超过 150 行
- [ ] 没有三元、`||` 默认值、`as any`
- [ ] 双向绑定用 `defineModel`
- [ ] 每个区块和声明上方有一行短注释
- [ ] 没有残留的空样式块、无调用的组件
