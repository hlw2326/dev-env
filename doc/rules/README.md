# DevEnv 规则

写代码前先读对应规则。所有规则只写"必须怎样、禁止怎样",不写背景。

| 文件 | 管什么 | 什么时候读 |
|------|--------|------------|
| [总则.md](总则.md) | 不兼容、不保底、禁三元、禁硬编码、命名要短 | 每次 |
| [命名.md](命名.md) | 变量、方法、文件、字段怎么起名 | 每次 |
| [后端.md](后端.md) | Go 分层、错误、Wails 绑定 | 改 `internal/` |
| [前端.md](前端.md) | 目录、组件、composable、API 层 | 改 `frontend/src` |
| [样式.md](样式.md) | 字号、图标、行高、PrimeVue 覆盖 | 写任何样式 |
| [数据库.md](数据库.md) | 迁移、改表同步清单 | 改表或仓库 |
| [站点.md](站点.md) | 建站流程、网关、目录与启动规则 | 改站点或网关 |
| [软件.md](软件.md) | 安装、卸载、守护进程、配置抽屉 | 改软件商店 |

## 优先级

1. 总则 > 其他所有规则。
2. 单项规则和总则冲突时,改规则,不要在代码里绕。
3. 新增规则写进对应文件,不另开文档。需要新类别才加新文件,并在上表登记。

## 文档本身的规则

- 全部中文。
- 只写规则和可执行的检查命令,不写讨论、待确认、决策过程。
- 一条规则一句话,能配一个"错/对"例子就配。
- 规则变了就改文件本身,不留"旧规则"章节。
