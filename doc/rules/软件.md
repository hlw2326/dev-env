# 软件

- 软件商城目录、版本、下载地址和校验值统一来自 catalog。
- 软件安装到 `%LOCALAPPDATA%\dev-env\software`，下载临时文件放 cache，安装失败清理临时目录。
- 解压必须做 zip-slip 路径检查，目标路径越界时整个安装失败。
- 已安装软件按 `kind` 和 `version` 区分；默认版本使用 `main` 标记，不在读取处动态替换版本。
- 软件状态只使用 `installing`、`installed`、`failed`，失败原因写入真实错误。
- 守护服务启动前检查可执行文件和端口，失败返回真实错误；不伪造运行状态。
- 所有托管服务统一使用 `infra/windowsservice` 查询服务归属和控制启停；识别运行状态必须校验安装目录或服务宿主子进程归属，禁止仅凭端口、进程名将外部安装或其他版本认作当前服务。
- 跨账号无法读取进程路径时，读取已注册的服务定义并验证服务宿主与监听进程的父子关系；查询仅申请所需的读取权限。
- 重启必须等待 Windows 服务完全停止和监听端口释放后再启动；服务账号的目录读取、日志写入和数据库目录写入权限在配置阶段准备，启动失败带出实际日志。
- 守护服务使用独立进程启动，不绑定 DevEnv 生命周期；应用重启后通过端口和进程名识别已有服务，只有用户明确停止时才结束服务。
- 停止服务结束整个进程树；服务日志写入统一日志目录并支持读取末尾内容。
- MySQL、MariaDB、PostgreSQL、MongoDB 的数据目录独立放在 `dbdata`，卸载软件不删除数据目录。
- 修改配置后明确返回是否需要重启；前端根据返回结果提示，不静默成功。
- 软件列表、配置和服务操作使用 `SoftwareAPI`，前端不直接访问仓库或进程管理器。
- 已有环境检测通过 `CommandInspector` 统一执行；检测定义集中在 `software.InspectionProbes`，新增商店类型必须同时提供只读版本探测和解析测试。
- 本机环境采用独立抽屉和用户主动查询；商店加载、打开安装窗口及安装事件不自动触发扫描，卡片仅显示已确认且未过期的版本徽章。
- 检测查询 PATH、适用的安装环境变量、原生 Windows 服务登记或用户明确选择的程序文件；不执行登记中的启动参数、不运行项目脚本，不自动下载运行依赖。检测任务必须有并发限制、输出限制和超时，超时仅清理检测进程树。
- 全部软件扫描由一次后端调用组织；公共接口故障集中显示一次，单项真实错误保留在查询详情，未查询和未发现不得渲染成失败。
- 外部环境只读展示，不自动写入托管软件记录，不计入 DevEnv 已安装数量；安装、卸载和服务控制不得因识别结果接管外部安装或改动其 PATH、配置和数据。
- 数据库客户端不等于服务端，Java 运行时不等于完整 JDK，.NET 运行时不等于 SDK；入口冲突、未发现、检测失败和覆盖范围不完整必须分别展示。
