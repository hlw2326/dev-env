# 软件

软件商店一页完成软件的安装、配置、启停、卸载。只提供四种:PHP、Node.js、MySQL、Redis。

## 一、目录

全部固定绝对路径,不用相对路径:

```
%LOCALAPPDATA%\DevEnv\
├── data\devenv.db  data\backups\
├── software\<kind>\<version>\
├── dbdata\mysql-<version>\      数据目录,与软件目录分开
├── cache\                       下载暂存
└── logs\sites\<站点名>\  logs\software\<kind>-<version>.log
```

- 卸载只删 `software\` 下对应版本目录。
- `dbdata\` 永远不随卸载删除,卸载时提示数据保留在哪。

## 二、下载源

| 软件 | 清单 | 校验 | 入口 |
|------|------|------|------|
| PHP | `https://downloads.php.net/~windows/releases/releases.json`,需跟随重定向 | 清单自带 `sha256` | `php-cgi.exe` |
| Node.js | `https://nodejs.org/dist/index.json` | 同目录 `SHASUMS256.txt` | `node.exe` |
| Redis | GitHub API `redis-windows/redis-windows` releases | 无 | 解压后查找 `redis-server.exe` |
| MySQL | 无清单,`https://dev.mysql.com/get/Downloads/MySQL-<主.次>/mysql-<版本>-winx64.zip` | 无 | `bin\mysqld.exe` |

- PHP 只用 **NTS**。文件名以清单为准,不手拼。
- Node 界面推荐最新 LTS,同时列出最新版。
- MySQL 用 `Range: bytes=0-0` 的 GET 探测版本是否存在(存在返回 206,不存在返回 404),只提供 8.4 LTS 与 8.0 两条线。
- Redis 的 GitHub 未认证限流 60 次/小时,清单在内存缓存 1 小时。
- 版本清单拉取失败:软件商店页显示错误和【重试】。**不设内置版本列表。**

每种软件列出的版本:

| 软件 | 列出 | 推荐 |
|------|------|------|
| PHP | 每个分支的最新小版本 | 8.3 分支 |
| Node.js | 最新版 + 近 3 个 LTS | 最新 LTS |
| MySQL | 8.4 最新、8.0 最新 | 8.4 |
| Redis | 最近 3 个 | 最新 |

## 三、数据模型

`system_software`,一行一个已安装版本:

`id kind version path state progress error main port autostart created updated`

- `kind`:`php` `nodejs` `mysql` `redis`。
- `state`:`installing` `installed` `failed`。
- `main`:默认版本,每个 `kind` 最多一个为 1。
- `port`:守护进程监听端口,PHP 与 Node 为 0。
- 配置只存在软件自己的配置文件里(`php.ini` `my.ini` `redis.conf`),数据库不重复存一份。库里只保留端口、随应用启动、默认版本。

## 四、安装流程

任何一步失败都如实失败,目录清理干净,状态记 `failed` 并带原因。

1. 同 `(kind, version)` 已 `installed` → `ALREADY_EXISTS`;`failed` 或 `installing` 残留 → 删除目录与记录后重装。
2. 写入记录:`state=installing, progress=0`。
3. 下载到 `cache\<kind>-<version>.zip.part`。响应码非 200 → `DOWNLOAD_FAILED`(带状态码)。约每 500ms 发一次 `task:progress`(0 到 70)。可取消。
4. 校验:有 sha256 的必须比对,缺失或不一致 → `DOWNLOAD_FAILED`。
5. 解压到 `software\<kind>\<version>.tmp`(progress 70 到 90)。防 zip-slip。只有一个顶层目录时去掉这一层。
6. 校验入口文件存在,否则 `INSTALL_FAILED`。
7. 按类型后处理(第五节)。
8. 目录改为正式名,记录改 `state=installed, progress=100`。该 `kind` 还没有 `main` → 本版本置 `main=1`。守护进程分配端口。PHP 与 Node 把 `software` 为 NULL 的同类型站点绑定到本版本。
9. 删除下载包,发 `task:completed`。

失败或取消:删除 `.part` 与 `.tmp`,记录标 `failed` + `error`,发 `task:completed` 带错误。

- 同一时间同一个 `(kind, version)` 只允许一个安装任务,取消靠内存 `map[key]cancel`。
- 应用启动时把残留的 `installing` 统一标为 `failed`(原因"安装被中断")并清理半成品。
- 安装进度走 `task:progress` 事件,前端不用定时器伪造。

## 五、后处理

| 软件 | 处理 |
|------|------|
| PHP | 由 `php.ini-development` 生成 `php.ini`:`extension_dir` 写绝对路径,启用 `curl fileinfo gd mbstring mysqli openssl pdo_mysql pdo_sqlite sqlite3 zip`,时区 `Asia/Shanghai` |
| Node.js | 无 |
| Redis | 找不到 `redis-server.exe` 则安装失败 |
| MySQL | 不在安装时初始化。首次启动执行 `mysqld --initialize-insecure --datadir=<dbdata>`,root 无密码,仅监听 `127.0.0.1` |

## 六、守护进程(MySQL、Redis)

装完即在"已安装"页签的版本行里直接有【启动】【停止】和端口,没有"创建服务"。

- 端口:安装时从起始端口(MySQL 3306、Redis 6379)起,取第一个未被其他版本占用且系统空闲的端口写入 `port`,之后固定。多版本可同时运行,各用各的端口。
- 启动前检查端口,被占用返回 `PORT_ALREADY_IN_USE`,不换端口。
- 启动后等待端口监听,最多 30 秒;超时杀进程并返回失败,附最后 20 行日志。
- 进程意外退出发 `service:status-changed`,带最后几行输出。
- 日志写 `logs\software\<kind>-<version>.log`。
- `autostart=1` 的守护进程在应用启动时拉起。
- `my.ini` 与 `redis.conf` 在首次启动前由 DevEnv 生成(端口、数据目录、仅监听 `127.0.0.1`)。
- 不做 MySQL root 密码、用户、数据库管理。

## 七、默认版本与卸载

- 默认版本(`main=1`)只在**创建站点时**取用,写入站点的 `software`。
- 站点版本创建时确定,之后只能在站点详情里手改。
- 卸载拒绝的情形(都给出具体站点名或进程):
  - 守护进程正在运行 → `SERVICE_RUNNING`
  - 有站点的 `software` 指向该版本 → `RUNTIME_IN_USE`,列出站点名
- 卸载的是默认版本:还有别的版本则把版本号最高的设为默认;是最后一个则直接卸载。

## 八、页面

两个页签:**全部软件**(卡片选版本并安装,安装中变进度条加【取消】,失败显示原因与【重试】)、**已安装**(按软件分组,一行一个版本:设默认、启停、设置、卸载)。另有分类筛选与搜索。

配置抽屉按软件类型拆组件,共用"配置文件全文编辑"与"日志"两个子组件:

| 软件 | 内容 |
|------|------|
| PHP | 概览;常用配置 `upload_max_filesize post_max_size memory_limit max_execution_time date.timezone display_errors`;扩展开关;`php.ini` 全文;日志 |
| Node.js | 只有概览 |
| MySQL | 概览(状态、启停、端口、随应用启动、打开数据目录);常用配置 `max_connections innodb_buffer_pool_size character-set-server`;`my.ini` 全文;日志 |
| Redis | 概览;常用配置 `maxmemory requirepass appendonly`;`redis.conf` 全文;日志 |

配置写入规则:

- 常用配置是对配置文件的"读取并改写单行",保留其余内容与注释。
- 保存前备份为 `<文件名>.bak`。写入失败如实报错。
- PHP 每个请求重读 `php.ini`,立即生效;MySQL、Redis 需重启,`SaveConfig` 返回 `restart=true`,抽屉显示【保存并重启】。
