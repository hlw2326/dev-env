# 总则

当前是开发模式。以下七条对前端、后端、数据库、文档一律生效。

## 一、不向下兼容

- 改字段、接口、表:同一次改动把迁移、仓库、领域模型、DTO、`wailsjs`、前端类型、页面全部改完。
- 旧字段、旧别名、旧参数、`deprecated`、"如果是旧格式则……"一律直接删。
- 看到能优化的地方直接重写,不为少改几行而绕开。
- 不探测旧库(`pragma_table_info`、`sqlite_master`),不迁移旧数据。
- 没有调用方的函数、类型、组件、样式、配置项,直接删。

## 二、不保底

有数据就是数据,没有就是空,由界面决定显示什么。

禁止:

```ts
a ? b : c                  // 三元
name || '未命名'            // 补默认
list ?? []                 // 空合并
msg.nickname?.[0]          // 可选链兜底
```

```go
if v == "" { v = "默认" }  // 读时补默认
```

规则:

- 默认值只在**一个源头**设置一次:数据库列 `DEFAULT`,或创建入参,或表单初始值。读取处不重复。
- 按类型区分的预设放一张表,创建时查一次:`var preset = map[Kind]Preset{...}`。
- 状态到文案用对象查表:`{running: '运行中'}[state]`,查不到就是空。
- Go 返回的切片不能是 nil,在 DTO 转换处统一 `make([]T, 0)`。
- 模板分支用 `v-if` / `v-else`,不用三元。
- 输入不合法就拒绝并返回 `INVALID_ARGUMENT`,不替用户改值。
- 不设静默替代:不设离线内置列表,不自动换端口,不"找不到就回退默认版本",不伪造数据。失败就明确报错。

允许:真正的分支逻辑。`if / else` 决定做不同的事、`v-if` 决定渲不渲染都正常。禁止的只是"为保底而补值"。

## 三、禁止硬编码

业务代码里不出现写死的字面量。同一个值只在一个源头定义,其他地方引用。

| 类别 | 禁止 | 源头 |
|------|------|------|
| 路径 | `"C:\\Users\\..."`、`"runtimes/"`、相对路径 | 路径只在一个 `paths` 包里由 `%LOCALAPPDATA%` 等系统变量拼出 |
| 端口、地址 | `80` `3306` `"127.0.0.1"` 散落在逻辑里 | 端口:设置项或 `preset` 表。回环地址:一个常量 |
| 下载源、接口 URL | 在服务或安装逻辑里拼字符串 | 只在 `infra/catalog` 里定义 |
| 版本号 | `"8.3.35"` `"24.21.0"` | 来自版本清单,代码里不写 |
| 魔法数字 | `30`(秒)`8`(并发)`500`(ms)`5`(备份数) | 具名常量,放在使用它的包顶部 |
| 类型、状态、事件名 | `"php"` `"running"` `"task:progress"` 到处写 | Go 用具名类型与常量,TS 用一份联合类型或对象 |
| 错误码、错误文案 | 在各处手写字符串 | 只用 `shared/errors` |
| 颜色、字号、间距、圆角 | `#16a34a` `14px` `0.8rem` | 只用 `style.css` 令牌 |
| 界面文案 | 同一句话在多处复制 | 状态文案用一张查表对象 |
| 表名、列名 | 在服务层拼 SQL | 只出现在 `infra/sqlite` 的仓库和迁移里 |

规则:

- 具名常量写在使用它的包或文件顶部,名字说明用途,不叫 `N` `TIMEOUT1`。
- 常量只被一处使用且含义自明时(如 `0` 表示未设置、`1` 步长),不必提取。
- 默认值是一种特殊的"源头",见第二节,只设置一次。
- 环境相关的值(用户目录、盘符、用户名、机器名)一律运行时取,不写进代码和文档示例以外的任何地方。
- 测试里可以写字面量,但路径用 `t.TempDir()`,端口用 `:0` 让系统分配。

## 四、不吞错

- 禁止 `_ = ...`、`x, _ := ...` 掩盖失败。错误要么返回,要么记日志后明确继续。
- 前端 `catch` 必须展示后端返回的错误消息,不写 `catch {}`。
- 不造假:文件不存在不模拟成功,下载非 200 不当成功,没装环境不伪造进程。

## 五、命名要短

详见 [命名.md](命名.md)。一句话:变量一个完整单词,方法 `xxxXxx`,完整单词不缩写。

## 六、合并重复

同样的逻辑出现多处,合并成一个方法或一个组件,不复制粘贴。

触发条件,满足任一条就合并:

- 相同或只差几个参数的代码出现 **两处以上**,且单处超过约 5 行。
- 同一段模板结构(卡片头、列表项、空状态、弹窗外壳、表单行)在两个以上位置重复。
- 同一个转换、校验、拼接、格式化在多处各写一份。

合并到哪里:

| 场景 | 位置 |
|------|------|
| Go,同包内重复 | 包内私有方法,放在使用它的文件里 |
| Go,跨包重复 | 按职责放到对应的包(`paths` `errors` 等),不建 `util` `common` 大杂烩 |
| TS,纯逻辑 | `utils/` 下按职责分文件 |
| TS,带状态的逻辑 | composable,见 [前端.md](前端.md) |
| 模板与样式重复 | 页面内重复:`comps/` 小组件;两个以上页面重复:提升为全局 `h-` 组件 |
| 样式重复 | 令牌或全局工具类,见 [样式.md](样式.md) |

合并时:

- 差异用参数、插槽、props 表达。一个方法的参数超过 3 个,或需要布尔开关切换两套行为,说明不该合并,拆开。
- 合并后调用方一次改完,旧的重复代码直接删,不保留两套。
- 名字按 [命名.md](命名.md) 起,不叫 `common` `helper` `base`。
- 只有一处使用、将来"可能"复用的,不提前抽象。出现第二处再合并。

## 七、不碰 git

用户没有明确说"提交""推送"等 git 指令,就禁止一切 git 操作。

- 禁止:`add` `commit` `push` `pull` `fetch` `merge` `rebase` `checkout` `switch` `restore` `reset` `stash` `branch` `tag` `clean` `rm` `mv`,以及任何会改动仓库状态的命令。
- 只读命令(`status` `diff` `log` `show`)同样不主动执行。要看改动,用读文件、搜索工具。
- 每次授权只对当次指令有效。用户说"提交一下",只做这次提交,不顺带推送,下次改动也不自动提交。
- 用户明确要求时才执行,并且只执行要求的那一条。例:说"提交"就只 `add` 指定文件加 `commit`,不 `push`。
- 不用 git 当撤销手段。改坏了直接改回来,不用 `checkout` `restore` `reset`。
- 删除文件用文件系统删除,不用 `git rm`。

## 自查

```bash
# 三元与兜底,结果应为 0
rg ' \? .+ : ' frontend/src --glob '*.{ts,vue}'
rg "\|\| ('|\"|\[|\{|[0-9])" frontend/src
rg '\?\?' frontend/src --glob '*.{ts,vue}'
# 吞错误,逐条确认
rg '_ = |, _ :?= ' internal
# 硬编码,逐条确认是否在源头
rg '[A-Za-z]:\\\\|%LOCALAPPDATA%|127\.0\.0\.1|https?://' internal --glob '*.go' -g '!*_test.go'
rg '#[0-9a-fA-F]{3,8}\b' frontend/src --glob '*.vue'
rg ':\s*[0-9.]+px' frontend/src --glob '*.vue'
# 构建
go build ./... && go test ./...
cd frontend && npx vue-tsc --noEmit && npm run build
```
