# 总则

当前项目处于开发模式，代码以当前结构为准，不为旧版本保留兼容层。

## 一、不向下兼容

- 修改字段、接口或表时，同一次改完迁移、仓库、领域模型、DTO、Wails 绑定、前端类型和页面。
- 旧字段、旧参数、旧别名和 `deprecated` 直接删除，不保留过渡分支。
- 不探测旧数据库结构，不迁移旧数据；开发库结构漂移时按明确的重置流程重建。
- 没有调用方的函数、类型、组件和样式直接删除。

## 二、不保底、不造假

- 默认值只在一个源头设置：数据库默认值、创建入参或表单初始值；读取处不重复补值。
- 输入不合法返回 `INVALID_ARGUMENT`，不替用户修改值。
- 文件不存在、运行环境未安装、下载失败和进程启动失败都必须返回真实错误。
- 不自动换端口、不自动换版本、不用内置列表伪造外部数据。
- Go 返回给 DTO 的切片必须是非 nil 切片。
- 前端 `catch` 必须展示后端返回的错误，不允许空 catch。

## 三、分层

```text
internal/domain       纯领域模型和规则
internal/ports         仓库、网关、进程、目录等接口
internal/app           业务编排
internal/infra         SQLite、网关、进程、安装器等实现
internal/shared        路径、错误等共享基础能力
internal/transport     Wails API、DTO 和事件
frontend/src/api       前端唯一的后端调用入口
frontend/src/views     页面和页面私有组件
frontend/src/components 全局 h- 组件
```

- `domain` 不依赖 `infra`、Wails 或前端。
- `infra` 不反向依赖 `app`。
- `transport` 只转换 DTO 和发送事件，不写业务流程。
- 依赖通过构造函数注入，不写无意义的 nil 守卫。

## 四、禁止硬编码

- 路径统一由 `internal/shared/paths` 生成，数据根目录为 `%LOCALAPPDATA%\dev-env`。
- 错误码统一使用 `internal/shared/errors`。
- 端口、地址、状态和事件名使用具名常量或统一类型。
- 颜色、字号、圆角和页面间距只使用 `style.css` 令牌。
- 版本、下载地址和校验值只来自 `internal/infra/catalog`。

## 五、布局与滚动

- 主布局 `main-content` 只负责承载路由，不设置页面正文内边距和滚动条。
- 页面正文内边距由 `h-page` 的 `.body.with-padding` 统一提供。
- 页面标题栏固定，滚动条只出现在 `h-page` 的 `.body.scrollable`。
- 可选 Boolean Prop 必须在组件源头明确默认值，不能依赖 Vue 的隐式 false。
- 弹窗头部和底部固定，弹窗内容区负责滚动；页面不能为同一层级重复添加 padding。

## 六、合并重复

- 相同模板在两个页面出现时提升为全局 `h-` 组件。
- 页面私有组件放在对应页面的 `comps/`，使用 `comp-` 标签。
- 纯逻辑放 `utils/`，带状态逻辑放页面或模块的 `use-xxx.ts`。

## 七、版本库

- 用户没有明确要求时不执行任何 Git 命令，包括只读命令和会改变仓库状态的命令。
- 不用 Git 撤销代码；修改错误直接用文件编辑修正。
- 删除文件使用文件系统操作，不使用 `git rm`。

## 八、验证

每次改动至少执行：

```text
go build ./...
go test ./...
cd frontend && npx vue-tsc --noEmit && npm run build
```

修改 Wails 绑定后重新生成 `wailsjs`，不手改生成文件。
