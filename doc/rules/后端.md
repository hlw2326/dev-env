# 后端

## 一、分层

```
internal/
├── domain/       领域模型与纯函数,不依赖 Wails 与数据库驱动
├── ports/        接口:仓库、Gateway、Runner、Catalog、Installer 等
├── app/          服务:编排业务,依赖 ports
├── infra/        实现:sqlite gateway process catalog installer hosts network events
├── shared/errors 标准错误码
└── transport/wails  SiteAPI SoftwareAPI SystemAPI、DTO、事件
```

- `domain` 不 import `infra`、`transport`、Wails。
- `infra` 不反向依赖 `app`。
- `transport` 只做 DTO 转换与事件发送,不写业务。
- 依赖通过构造函数注入,注入后必然存在,**不写 `if x != nil` 守卫**。

## 二、错误

- 错误一律返回,用 `shared/errors` 的标准码:`INVALID_ARGUMENT` `ALREADY_EXISTS` `DOWNLOAD_FAILED` `INSTALL_FAILED` `PORT_ALREADY_IN_USE` `SERVICE_RUNNING` `RUNTIME_IN_USE` `RUNTIME_NOT_INSTALLED` `DATABASE_SCHEMA_MISMATCH` `MIGRATION_FAILED`。
- 不用 `panic` 处理启动失败。启动失败弹出错误对话框后退出。
- `json.Unmarshal` 失败要返回,不忽略。
- 查询要先判 `err`,再判是否存在。
- 创建流程中某步失败(如克隆)直接返回该错误,不用 `os.MkdirAll` 之类掩盖。

## 三、不造假

- `Runner.Start` 目标文件不存在就返回错误,不模拟 PID、不写假日志。
- 下载响应码非 200 返回 `DOWNLOAD_FAILED`,带状态码。
- 没有校验和的软件(MySQL、Redis)不校验是软件属性;有校验和的软件取不到就失败,不跳过。
- 日志读取真实文件末尾 N 行,文件不存在返回空切片。
- 站点没有 `status` 列。运行状态由网关路由表和进程管理器实时给出。

## 四、DTO 与 Wails

- DTO 字段齐全,切片不为 nil,前端不再补默认。
- DTO 与领域模型字段同名,不另起别名。
- `Result` 统一为 `{ok, message}`。`restart` 只在 `SaveConfig` 的返回里额外出现。
- 事件载荷用完整单词键:

| 事件 | 载荷 |
|------|------|
| `task:progress` | `{kind, version, progress, message}` |
| `task:completed` | `{kind, version, ok, error}` |
| `service:status-changed` | `{id, running, pid, message}` |
| `site:status-changed` | `{id, state, message}` |

- 改了绑定后运行 `wails generate module` 重新生成 `wailsjs`,不手改。

## 五、路径与进程

- 数据与软件目录固定在 `%LOCALAPPDATA%\DevEnv`,一律绝对路径,不依赖进程工作目录。
- 路径一律做穿越检查;解压做 zip-slip 检查,出界整个安装失败。
- 子进程隐藏控制台窗口;停止进程要结束整个进程树。
- 网关只监听 `127.0.0.1`,不监听 `0.0.0.0`。没有登录机制,不得对外暴露。

## 六、测试

- 改了逻辑就补或改测试;每个阶段 `go build ./...` 与 `go test ./...` 通过才继续。
- 仓库测试用临时目录里的真实 SQLite。
- 下载与安装用 `httptest` 模拟源,覆盖:成功、非 200、校验不一致、zip-slip、缺入口文件、中途取消、失败后目录被清理。
- Gateway 用 `httptest` 覆盖:Host 匹配、路径穿越、隐藏文件拒绝、反向代理与 WebSocket、PHP 回落到入口文件。
- Runner 用真实小进程测启动、状态、输出尾部、结束进程树。
- 依赖本机环境的测试(真实 `php-cgi.exe`)不存在就跳过,并在输出里写明跳过。
