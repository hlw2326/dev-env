# 项目

## 项目模板

- 项目类型由后端项目模板注册表统一提供，模板包含显示名称、图标、运行环境、启动命令模式和能力集合。
- 详情页使用公共能力模板组合渲染：域名、运行目录、运行环境、启动命令、自动启动、Nginx 和日志都是可复用能力；项目类型只声明能力，不在前端重复维护类型数组。
- 类型专属字段通过模板或项目插件贡献，不能把 PHP、Node.js 等类型条件散落到多个页面和后端 `switch` 中。
- 新增项目类型只需要注册项目模板、检测规则和必要的插件，不修改项目基础表结构；公共能力由已有模板复用。

## 创建

- Web 项目创建必填：类型、名称、域名；类型为 `static`、`php`、`node`、`python`、`go`、`rust`、`java`。
- Electron 和小程序项目类型分别为 `electron`、`miniprogram`，只需要名称和项目目录，不填写域名，不经过 Nginx。
- Electron 项目默认启动命令为 `pnpm dev`，支持在项目详情中修改；项目不随 DevEnv 自动启动。
- 根目录和运行目录在创建表单中明确填写；目录不存在时创建。
- 默认根目录来自设置，软件版本由后端选择该类型的 `main` 版本。
- 空目录写入对应示例入口：静态 `index.html`、PHP `index.php`、Node `package.json` 与 `server.js`。
- Python、Go、Rust、Java 空目录分别写入 `app.py`、`go.mod`/`main.go`、`Cargo.toml`/`src/main.rs`、`Main.java` 示例入口。
- 缺少 PHP 或 Node 环境时允许创建，启动时明确返回缺少环境，不伪造运行状态。
- Python、Go、Java 项目绑定软件商城中的对应运行环境；Rust 项目使用系统 PATH 中的 `cargo`，缺少运行环境时允许创建，启动时明确返回缺少环境。
- 删除项目只删除数据库记录，不删除项目目录。

## 项目插件

- 项目详情由基础页签和动态插件页签组成；插件由后端根据项目类型、项目文件和已安装软件自动探测，不把插件字段硬编码到项目表。
- PHP 项目检测到 `composer.json` 时提供 Composer 插件；Node.js、Electron 和小程序项目检测到 `package.json` 时提供 Node 包管理插件。
- Python 项目检测到 `requirements.txt` 或 `pyproject.toml` 时提供 Python 依赖插件；Go 项目检测到 `go.mod` 时提供 Go 模块插件；Rust 项目检测到 `Cargo.toml` 时提供 Cargo 插件；Java 项目检测到 Maven 或 Gradle 构建文件时提供 Java 构建插件。
- 插件操作必须通过统一插件接口执行，长任务立即返回，并使用 `project:plugin-status-changed` 推送运行状态和真实错误。
- 插件由统一注册定义描述支持的项目模板、所需项目文件、运行环境和操作；服务按注册定义探测，不在项目服务中维护每个插件的文件匹配 `switch`。
- 新增插件只扩展插件注册定义、探测逻辑、操作命令和详情组件，不修改项目基础模型和已有页签。

## Git 管理

- 项目列表显示每个项目的 Git 仓库、未提交变更和工作区干净状态；项目详情提供统一 Git 管理页签。
- Git 状态由本机 Git 命令实时读取，不持久化到项目表；Git 不可用时显示真实错误。
- 初始化仓库和本地提交由用户显式触发。提交统一暂存该项目仓库内全部已跟踪、未跟踪和已暂存变更，不自动推送远端。
- 项目目录若只是父仓库中的子目录，禁止初始化或提交，避免误操作整个父仓库。
- 自动版本递增必须基于已识别的版本文件和三段数字版本；不识别时禁用开关并说明原因。版本递增规则见《Git集成.md》。
- 未安装 Git 与项目未启用 Git 必须区分；启用仓库需要用户明确点击，不自动初始化。
- 远端 URL 使用项目本身的 Git 配置。获取远端状态不合并工作区；推送与移除远端必须确认，不强推、不自动推送。
- 待推送和落后状态基于本地上游引用，未获取最新远端状态时不得承诺已经与服务器同步。
- Git 写操作按仓库互斥，前端显示 loading，失败必须恢复本次自动版本修改和原暂存区或报告恢复失败。

## 手动发布

- PHP、Node.js 通过 `server-sync` 能力提供 SSH/SFTP 服务器同步，小程序通过 `wechat-upload` 能力提供微信开发版本上传；入口由项目模板控制。
- 发布提供器经 `ports.DeploymentProvider` 注入，配置与历史使用独立单数表，不扩充项目基础字段。
- 保存配置、项目启动、文件变化、Git 提交、应用启动均不触发发布。必须先生成预览，再由用户明确确认；预览一次性使用且有有效期。
- 发布前校验文件摘要并创建过滤后快照，排除环境变量、版本库、私钥和依赖目录；服务器用户数据目录默认保护。禁止目录穿越和符号链接。
- SSH 必须校验用户已核验的主机指纹；密码和口令只在单次操作内存中使用，禁止落库或写日志。
- 服务器同步不删除额外文件、不执行远程脚本、不重启服务；只保证单文件原子替换，不伪造整批回滚或零停机。
- 小程序只上传开发版本，提审及正式发布仍由用户在微信后台完成。不得将上传成功显示为已上线。
- 长任务异步执行，按项目和目标互斥，支持取消并保存真实结果。只在运行时轮询，不自动重试或恢复中断任务。

## 目录和域名

- `root` 是项目根目录，`run` 是根目录内的相对运行目录，空值表示根目录本身。
- 运行目录禁止绝对路径和 `..` 穿越。
- 自动识别入口命中即停止，未命中返回空，不猜框架。
- 域名在数据库层唯一；自定义域名只有启用 hosts 后才写入系统 hosts。

## 网关和生命周期

- 网关监听 `127.0.0.1`，端口被占用时失败并提示用户，不自动换端口。
- PHP 使用 php-cgi；Node、Python、Go、Rust、Java 使用进程树管理，并通过 `PORT` 环境变量传递项目端口。
- Node、Python、Go、Rust、Java 项目统一通过 Nginx 反向代理到项目端口，Electron 仍然只做本地调试并绕过 Nginx。
- 启动 Nginx 和 PHP FastCGI 服务时只配置 DevEnv 自有运行目录及日志目录权限，不检测或修改项目目录权限；项目目录不可访问时由实际网站请求返回错误。
- PHP location 不使用 `try_files $fastcgi_script_name =404` 提前返回 Nginx 404；请求交给 PHP FastCGI，由运行环境或项目返回真实错误。
- 路由表整体替换，运行状态由网关和进程管理器实时计算，不增加项目 `status` 列。
- 每个项目有访问日志；日志读取真实文件，不存在返回空切片。
- Nginx 配置检查前创建 Nginx 前缀所需的 `logs`、`vhosts` 和临时目录。

## Nginx 高级配置

- 项目详情提供“Nginx 高级配置”页签，用于编辑当前项目 `server` 区块内的附加指令。
- 基础 `server`、域名、根目录、运行环境和反向代理配置仍由系统生成，不能通过片段覆盖。
- 保存前后必须使用 Nginx 配置检查；片段只允许影响当前项目，不得写入 `http`、`events` 或额外的 `server` 区块。
- 项目配置文件由系统统一渲染，用户不直接编辑生成文件；高级配置持久化在项目记录中。
- PHP 项目可选择项目根目录下的 `.env`、`.env.dev`、`.env.prod` 等环境变量文件；未选择时优先使用 `.env.dev`。
- 启动 PHP 项目时，DevEnv 只从所选文件名提取环境名：`.env.dev` 生成 `fastcgi_param ENV_NAME "dev";`，`.env.prod` 生成 `fastcgi_param ENV_NAME "prod";`；禁止读取或将环境文件中的数据库、缓存、会话等键值转换为 Nginx FastCGI 参数。环境文件只允许位于项目根目录内。
- 环境变量文件是可选配置；已选择的文件不存在时跳过 `ENV_NAME` 注入并继续启动项目，路径越界、名称非法或目标为目录时仍然返回错误。
- `.env.example` 和 `.env.sample` 仅作为模板，不会自动加载；服务器同步仍然排除环境变量文件。
