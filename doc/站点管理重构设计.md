# DevEnv 站点管理重构设计

**目标：** 像宝塔面板一样，建站只要「选类型、填名称、填域名」。PHP 版本、Web 服务器、端口、目录、启动命令全部自动处理。
**阶段：** 开发阶段，数据库与旧代码全部重构，不保留任何兼容层。
**取代：** 此前的《网站管理模块设计》《软件商店与运行环境管理设计》《服务实例自动创建与版本切换设计》，三份已删除。

---

## 一、为什么必须重构

下面每一条都在代码里核对过，不是推测。

| # | 问题 | 依据 |
|---|------|------|
| 1 | 建站向导 4 步、20 个字段，要选运行环境、服务实例、上游端口、证书 | `sites/use-wizard.ts` 的 `form` |
| 2 | **"Nginx"是假的**：站点由 Go 的 `http.Server` 按 Host 分发；`Check` 只数花括号；`Reload` 是空函数；软件商店装的 `nginx.exe` 没有任何站点使用 | `internal/infra/nginx/manager.go` |
| 3 | **进程管理器造假**：可执行文件不存在、或是 nginx.exe / php-cgi.exe 时，伪造 PID 和"启动成功"日志 | `internal/infra/process/manager.go` 的 `Start` |
| 4 | **安装吞错**：下载返回非 200 直接 `return nil`，`Install` 里 `_ =` 忽略错误，仍标记为已安装，结果是目录为空却显示"可用" | `internal/app/runtime.go` 的 `downloadAndExtractZip` |
| 5 | **Node / Go / Python 站点从未真正运行**：`Meta.Cmd` 只被读写，没有任何地方执行；`buildSpec` 只支持 php、nginx、mysql、redis | 全库 grep `.Cmd` |
| 6 | 当前工作区 `go build ./...` 直接失败，`site.go` 有 6 处错误 | 本次实测 |
| 7 | 概念太多：运行环境、服务实例、站点、任务，装完软件还要手动"创建服务" | 导航 7 项 |
| 8 | 安装路径用相对路径 `runtimes/`，依赖进程工作目录，结果 93MB 软件被装进了仓库；仓库根还有 `vue-tsc`、`wails` 两个误生成的 0 字节文件 | 仓库根目录 |

结论：问题出在架构上，修补不了。

## 二、产品原则

1. **用户只做一件事**：选类型，填名称，填域名，点创建。其余都有默认值，高级项折叠。
2. **装完软件就能用**：没有"服务实例"这个概念。
3. **不造假**：启动失败就报真实错误；没装环境就明确提示，并给一键安装。
4. **不碰用户目录**：删除站点只删记录，永远不删项目目录。
5. **只有三个页面**：网站、软件商店、设置。左侧导航里的控制台、运行环境、服务实例、任务作业全部删除，软件的安装、配置、启停都在软件商店一页完成。

被砍掉的功能（需要时再单独设计，不留半成品）：

| 功能 | 原因 |
|------|------|
| 控制台、运行环境页、服务实例页、任务作业页 | 网站状态在网站页，软件的安装、配置、启停在软件商店页，安装进度在软件卡片上 |
| Git 克隆 / 拉取 / 推送 | 与"傻瓜式建站"无关，用户自己有 git |
| SSL / HTTPS | 本地开发用 `http://xxx.localhost` 即可 |
| Nginx 配置编辑、配置历史快照 | 没有真实 Nginx，编辑出来的配置没有任何效果 |
| Go、Python 站点类型 | 从未真正运行过；Node 站点的启动命令已能跑任意命令，以后需要再加 |
| 多语言（i18n） | 项目只有中文界面，zh-CN 文件已被删除，翻译层只增加复杂度 |
| 服务实例、任务表 | 见第五节 |

### 2.1 编码约定

本项目处于开发模式，下面三条对前后端、数据库、文档一律生效。

**一、不向下兼容，直接用最新写法**

- 改字段、改接口、改表：同一次改动里把数据库、仓库、领域模型、DTO、前端类型、页面全部改完，旧的直接删。
- 不留旧字段、旧别名、旧参数、`deprecated` 标记，不写"如果是旧格式则……"的分支。
- 看到能优化的地方直接重写，不为了少改几行而绕开。

**二、不做保底，有就是有，没有就是空**

- 禁止用三元表达式、`||`、`??`、`if v == "" { v = 默认 }` 给值"补默认"。例如不写 `a ? b : c`、`name || '未命名'`、`list ?? []`。
- 值从哪来就是哪个值：有数据就用数据，没有就是空字符串、0、空数组，由界面自己决定显示什么。
- 默认值只在**一个源头**设置一次（数据库列的 `DEFAULT`，或创建时的入参），读取的地方不再重复兜底。
- 状态到文案的映射用对象查表（`{running: '运行中'}[state]`），查不到就是空，不写 `?:` 链。
- 真正的分支逻辑不受限制：`if / else` 决定做不同的事、`v-if` 决定渲不渲染都是正常的，禁止的只是"为了保底而补值"。
- 这条同样约束设计：不设"离线内置列表""端口被占自动换一个""找不到就回退到默认版本"这类静默替代。失败就是失败，明确报错，用户自己决定。

**三、命名尽量短，但完整的单词不缩写**

先看有没有一个完整的短单词能表达；有就用它，**绝不把一个完整单词砍成缩写**。没有合适的单词才用两个词。

| 对象 | 规则 | 例子 |
|------|------|------|
| 变量、字段、数据库列、DTO 键 | **一个完整单词** | `id` `kind` `name` `root` `version` `port` `state` `progress` `error` `message` `software` `command` `config` |
| 方法、函数 | 动词在前，`xxxXxx` 两个完整单词的小驼峰 | `findRun` `saveConfig` `loadSite` `bindSite` |
| 类型 | 一到两个完整单词的名词 | `Site` `Software` `Route` `Result` |
| 文件 | 一个完整单词 | `site.go` `software.go` `config.go` |
| 事件名 | 沿用标准名 | `task:progress` |

- **禁止缩写的例子**：`ver`、`conf`、`soft`、`cmd`、`pct`、`err`、`msg`、`desc`、`cat`、`rec`、`dir`、`Res`、`Req`、`Stat`、`Prefs`、`Ext`。它们都有完整的短单词，必须写全。
- **允许保留的惯用缩写**只有这几个，因为它们本身就是通用词，写全反而别扭：`id`、`pid`（进程号）、`url`、`ok`、`ctx`（Go 的 `context.Context` 参数）、`err`（仅限 Go 函数内的局部错误变量，数据库列、DTO、事件载荷里一律写 `error`）。
- 一个单词表达不了时用两个词：`autostart` 是一个词（随应用启动）；"运行目录"没有单个完整单词，字段叫 `run`（见下）；更多情况用 `xxxXxx`，如 `writeConfig`。
- `main` 表示"默认版本"：`default` 是 Go、SQL、JS 的保留字，不能当字段名。
- `run` 表示运行目录：它是完整单词，但含义比 `runDirectory` 窄，这是为了字段短而做的取舍，不是缩写。若觉得有歧义，改成 `entry` 或 `public` 都可以，请在评审时告诉我。
- Wails 要求绑定到前端的 Go 方法首字母大写，对外写成 `FindRun`、`SaveConfig`；包内私有方法写成 `findRun`、`saveConfig`。
- 表名保留 `system_` 前缀与完整单词（`system_software`）。

**本文档里的字段与方法名已按此规则统一**，下面所有表格、接口、事件都使用完整短词。旧名与新名的对应：

| 旧 | 新 | 旧 | 新 |
|----|----|----|----|
| `version` / `ver` | `version` | `software_id` / `softwareId` / `soft` | `software` |
| `status`（安装状态） | `state` | `run_dir` / `runDir` | `run` |
| `progress` / `pct` | `progress` | `start_cmd` / `startCmd` / `cmd` | `command` |
| `error` / `err` | `error` | `auto_start` / `autoStart` / `auto` | `autostart` |
| `is_default` / `isDefault` | `main` | `domain`（域名表） | `host` |
| `created_at` `updated_at` | `created` `updated` | `softwareVersion` | `version` |
| `msg` / `desc` / `cat` / `rec` | `message` / `description` / `category` / `recommended` | `conf` / `Conf` | `config` / `Config` |
| `live` / `up` | `running` / `listening` | `have` | `installed` |
| `Prefs` / `SavePrefs` | `Settings` / `SaveSettings` | `Res` / `Req` / `Stat` / `Ext` | `Result` / `Request` / `Status` / `Extension` |

**这组约定带来的几处设计调整**（"不做保底"的直接结果）：

1. **站点版本不再"跟随默认"。** 站点创建时就把当时的默认版本写进 `software`，之后默认版本再变，已有站点不受影响。`software` 为空（NULL）只表示"当时没装环境"，界面显示"缺少环境"和【一键安装】，装好后由服务把这些站点绑定到刚装的版本。读取时没有"为空则取默认"的分支。
2. **没有"离线内置版本列表"。** 版本清单拉取失败就在软件商店页显示错误和【重试】。
3. **网关端口被占用不再自动换端口。** 网关启动失败就如实报错，设置页显示原因，用户自己改端口。
4. **"自动识别运行目录"识别不到就是空**（即根目录本身），不再默认猜 `/public`。需要 `/public` 的项目由用户在创建时选择。
5. **缺少校验文件时不再"跳过校验"。** 取不到校验和就安装失败。

## 三、用户流程

### 3.1 创建网站

一个对话框，三个必填项：

```
┌───────────────────────────────────────┐
│ 创建网站                               │
│                                        │
│ 类型   (●) PHP  ( ) Node.js  ( ) 静态  │
│ 名称   [ blog                       ]  │
│ 域名   [ blog.localhost             ]  │ ← 填名称后自动生成
│                                        │
│ 根目录 [ D:\www\blog          ] [选择]  │ ← 默认 <站点根>\<名称>
│ 运行目录 [ 自动识别          ▾ ]        │ ← /  /public  /web  /dist  自定义
│                                        │
│ ▸ 更多设置（运行环境版本、启动命令）    │
│                                        │
│              [取消]   [创建]           │
└───────────────────────────────────────┘
```

**根目录**和**运行目录**直接放在创建对话框里，不折叠，因为这两项决定网站能不能打开。"更多设置"默认折叠，只放运行环境版本和 Node 的启动命令。

### 3.2 默认值

| 项 | 默认 | 说明 |
|----|------|------|
| 域名 | `<名称>.localhost` | `*.localhost` 浏览器自动解析到本机，**不用改 hosts，不需要管理员权限** |
| 根目录 | `<站点根>\<名称>` | 项目代码所在目录。站点根默认 `%USERPROFILE%\DevEnv\www`，可在设置里改 |
| 运行目录 | 自动识别 | 网站入口所在目录，相对根目录填写，见 3.2.1 |
| PHP 版本 | 创建时的默认版本 | 创建时写入 `software`，之后不再随默认版本变化，见 2.1 |
| Node 版本 | 创建时的默认版本 | 同上 |
| Node 启动命令 | 自动探测 | 见 3.3 |
| Node 端口 | 自动分配，从 3000 起 | 创建时落库，通过环境变量 `PORT` 传给进程 |
| 目录为空 | 写入示例首页 | 静态写 `index.html`，PHP 写 `index.php`，Node 写 `package.json` 与 `server.js` |
| 网关端口 | 80 | 被占用时网关启动失败，设置页显示原因，由用户改端口；不自动换端口 |

### 3.2.1 根目录与运行目录

两个目录分开，因为很多框架的代码在项目根，而对外只暴露其中一个子目录。

| 名称 | 含义 | 例子 |
|------|------|------|
| 根目录 | 项目所在目录，Git、`composer.json`、`package.json`、`.env` 都在这里 | `D:\www\demo` |
| 运行目录 | 网站入口所在目录，相对根目录。**网关的文档根就是它**，访问不到它之外的任何文件 | `/public`，即 `D:\www\demo\public` |

以 ThinkPHP 为例：项目放在 `D:\www\demo`，入口是 `D:\www\demo\public\index.php`。根目录填 `D:\www\demo`，运行目录选 `/public`。`app/`、`config/`、`.env` 在运行目录之外，浏览器访问不到，这正是要的安全效果。

运行目录的选项：`/`（根目录本身）、`/public`、`/web`、`/dist`、自定义（输入相对路径）。默认"自动识别"，规则如下，命中即停，**都不命中就是空（根目录本身），不猜**：

| 类型 | 顺序 |
|------|------|
| PHP | `public/index.php` → `web/index.php` → 根目录有 `index.php` 则为空 |
| 静态 | 根目录有 `index.html` 则为空 → `dist/index.html` → `public/index.html` |
| Node | 空，不影响网关；启动命令的工作目录取运行目录 |

规则：

- 自动识别只看目录特征，不识别具体框架；识别错了用户在创建时或详情里改，**改完立即生效**，无需重启。
- 运行目录必须落在根目录内，含 `..` 或绝对路径一律拒绝。
- 创建时目录不存在就建出来：空项目由用户选 `/public`，会同时创建 `<根目录>\public` 并在其中写入示例首页；你把代码放进根目录即可。
- PHP 入口回落到运行目录下的 `index.php`，ThinkPHP、Laravel 的路由不需要配置伪静态。

### 3.3 Node 启动命令探测

按顺序，命中即停：

1. `package.json` 的 `scripts.start` → `npm start`
2. `package.json` 的 `main` 字段 → `node <main>`
3. 目录下存在 `server.js`、`app.js`、`index.js` → `node <文件>`
4. 都没有 → 创建成功，但状态显示"未配置启动命令"，详情里提示去填

命令里可以写 `%PORT%`，进程启动时展开。例如 Vite 项目写 `npm run dev -- --port %PORT%`。

### 3.4 运行环境没装怎么办

创建不拦截。站点列表里显示"未安装 PHP 环境"，旁边一个按钮【一键安装】，点击后安装推荐版本并自动把站点跑起来。

### 3.5 访问网站

- 点域名或【打开】：用系统浏览器打开 `http://<域名>[:网关端口]/`。
- `*.localhost` 域名无需额外操作。
- 自定义域名（如 `blog.test`）需要写 hosts：设置里有"自动写入 hosts"开关，默认关。开启后需要管理员权限运行；没有权限时**如实提示**，并给出要手动添加的那一行，不假装成功。

### 3.6 启动与停止

| 类型 | "运行中"的含义 | 启动做了什么 |
|------|----------------|--------------|
| 静态 | 网关在提供该站点 | 把站点加入网关路由表 |
| PHP | 同上，PHP 在每次请求时执行 | 同上，并检查 php-cgi 是否存在 |
| Node | 子进程存活且端口已监听 | 启动进程，等待端口就绪（最多 30 秒），再加入路由表 |

应用启动时，设了"随应用启动"的站点自动启动。停止 Node 站点会结束整个进程树。

### 3.7 删除网站

确认框只有一句话："只删除站点记录，不会删除项目目录"。没有"同时删除目录"的选项。

## 四、整体架构

```
┌────────────┐   Wails 绑定    ┌─────────────────────────────────────────┐
│ Vue 前端    │ ◄────────────► │ transport/wails  (SiteAPI SoftwareAPI    │
│ 网站/软件/  │    事件         │                    SystemAPI)            │
│ 设置        │                 ├─────────────────────────────────────────┤
└────────────┘                 │ app  SiteService  SoftwareService         │
                               │      SettingService                       │
                               ├──────────────┬──────────────────────────┤
                               │ domain       │ ports（接口）              │
                               │ site software│ repos / Gateway / Runner  │
                               │ setting      │ Catalog / Installer / ... │
                               ├──────────────┴──────────────────────────┤
                               │ infra: sqlite  gateway  process  catalog │
                               │        installer  hosts  network  events │
                               └─────────────────────────────────────────┘
                                   │                     │
                         SQLite（元数据）      127.0.0.1:网关端口 ──► 静态 / php-cgi / Node 子进程
```

沿用现有分层约束：`domain` 不依赖 Wails 与数据库驱动，`infra` 不反向依赖 `app`，`transport` 只做 DTO 转换与事件，不写业务。

### 4.1 网关

一个 HTTP 服务监听 `127.0.0.1:<网关端口>`，按请求的 `Host` 匹配站点，再按类型处理：

| 类型 | 处理 |
|------|------|
| 静态 | 提供文件；目录请求找 `index.html`；找不到返回 404 |
| PHP | 存在的非 `.php` 文件直接返回；存在的 `.php` 文件交给 php-cgi；其余请求回落到入口 `index.php`（保留原始 `REQUEST_URI` 与 `QUERY_STRING`，不再往查询串里塞 `s=`） |
| Node | 反向代理到 `127.0.0.1:<站点端口>`，支持 WebSocket |

- **只监听回环地址**，不暴露到局域网。没有登录机制，所以不能监听 `0.0.0.0`。
- Host 未匹配任何站点时，返回一个简单页面列出所有站点。
- PHP 每个请求启动一次 `php-cgi`，并发上限 8，单请求超时 60 秒。不使用 FastCGI 常驻池，原因见第十二节。
- 拒绝访问 `.git`、`.env`、`.htaccess` 等隐藏路径，路径一律做穿越检查。
- 每个站点一个访问日志文件，每次请求追加一行。

## 五、数据模型

沿用约定：表名 `system_` 前缀，主键 `INTEGER PRIMARY KEY AUTOINCREMENT`（Go `int64`、TS `number`），时间为 UTC RFC 3339 字符串，开启外键、WAL、`busy_timeout`。

### 5.1 保留与删除

| 表 | 处理 |
|----|------|
| `system_runtime_versions` | 重做为 `system_software` |
| `system_sites` | 重做，列从 22 个减到 12 个 |
| `system_site_domains` | 新增 |
| `system_app_settings` | 保留 |
| `system_schema_migrations` | 保留，按《数据库迁移与升级设计》重做 |
| `system_service_instances` | **删除**，守护进程的端口和启动状态并入 `system_software` |
| `system_tasks` | **删除**，安装进度记在 `system_software` 自身，进度走 `task:progress` 事件 |
| `system_git_status` | **删除**，全库无人读写 |

### 5.2 system_software：已安装的软件

一行 = 一个已安装的版本。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PK | |
| `kind` | TEXT NOT NULL | `php` `nodejs` `mysql` `redis` |
| `version` | TEXT NOT NULL | 如 `8.3.35` |
| `path` | TEXT NOT NULL | 安装目录绝对路径 |
| `state` | TEXT NOT NULL | `installing` `installed` `failed` |
| `progress` | INTEGER NOT NULL DEFAULT 0 | 0 到 100，仅安装中有意义 |
| `error` | TEXT NOT NULL DEFAULT '' | 失败原因 |
| `main` | INTEGER NOT NULL DEFAULT 0 | 默认版本，每个 `kind` 最多一个为 1 |
| `port` | INTEGER NOT NULL DEFAULT 0 | 守护进程监听端口，PHP 与 Node 为 0 |

| `created` `updated` | TEXT NOT NULL | |

约束：`UNIQUE (kind, version)`；索引 `(kind, state)`。

与旧表相比去掉了 `architecture`（只支持 x64）、`metadata_json`（原本塞默认标记和 variant，现在是正式列）。

### 5.3 system_sites：网站

| 字段 | 类型 | 说明 |

| `id` | INTEGER PK | |

| `kind` | TEXT NOT NULL | `static` `php` `node` |

### 6.1 目录规划

卸载软件只删 `software\` 下对应版本目录。`dbdata\` 里的数据库数据永远不随软件卸载删除，卸载时提示数据保留在哪。

### 6.2 软件目录与下载源

只提供四种软件。下表是 2026-10-14 实测的结果。

| 软件 | 版本清单来源 | 下载地址规则 | 校验 | 入口文件 |
|------|--------------|--------------|------|----------|
| PHP | `https://downloads.php.net/~windows/releases/releases.json`（`windows.php.net` 会 302 到这里，需跟随重定向） | 清单里每个分支的 `nts-*-x64.zip.path`，拼 `https://downloads.php.net/~windows/releases/` 前缀；已归档的旧小版本在 `.../releases/archives/` | 清单自带 `sha256`，下载后校验 | `php-cgi.exe` |
| Node.js | `https://nodejs.org/dist/index.json` | `https://nodejs.org/dist/v<版本>/node-v<版本>-win-x64.zip` | 同目录 `SHASUMS256.txt`（本次未实测，实现时验证；取不到校验文件则安装失败，不跳过） | `node.exe` |
| Redis | GitHub API `redis-windows/redis-windows` 的 releases | 资产 `Redis-<版本>-Windows-x64-cygwin.zip` | 无 | 解压后探测（见 6.5） |
| MySQL | 无清单接口 | `https://dev.mysql.com/get/Downloads/MySQL-<主.次>/mysql-<版本>-winx64.zip`，会 302 到 `cdn.mysql.com/archives/...` | 无 | `bin\mysqld.exe` |

实测中确认的事实：

- PHP 清单覆盖 7.4、8.0 到 8.5 共 7 个分支，NTS 与 TS 都有；本项目只用 **NTS**（`php-cgi` 要用 NTS）。7.4 用 vc15 构建，8.0 到 8.3 用 vs16，8.4 起用 vs17，文件名以清单为准，不手拼。
- Node 的"最新版"（`v26.11.1`）不是 LTS，LTS 是 `v24.21.0`（Krypton）。界面推荐 LTS，同时列出最新版。
- MySQL 的 `dev.mysql.com/get/...` 对**存在的版本返回 206 且 `Content-Range` 约 260MB**，对**不存在的版本返回 404 的 HTML 页**，所以可以用 `Range: bytes=0-0` 的 GET 探测版本是否存在。8.4.11 存在，8.4.12 不存在；8.0 线最新到 8.0.46。MySQL 官网首页现在主推 `26.7.0` 的新版本号体系，本项目只提供 8.4 LTS 与 8.0 两条线。
- Redis 的 GitHub API 未认证限流 60 次/小时，版本清单在内存里缓存 1 小时；限流或失败时如实显示错误，不用内置版本替代。

### 6.3 版本清单策略

每种软件在界面上只列最近的若干版本，避免长列表：

| 软件 | 列出 | 推荐 |
|------|------|------|
| PHP | 每个分支的最新小版本 | 8.3 分支 |
| Node.js | 最新版 + 近 3 个 LTS | 最新 LTS |
| MySQL | 8.4 最新、8.0 最新（启动时探测存在性） | 8.4 |
| Redis | 最近 3 个 | 最新 |

离线或接口失败时，软件商店页显示错误原因和【重试】，**没有内置版本列表**。安装本来就需要联网，没有网络时列出版本也装不上。

### 6.4 安装流程

任何一步失败都**如实失败**，目录清理干净，状态记为 `failed` 并带上原因。

```
1. 同 (kind, version) 已 installed → 返回 ALREADY_EXISTS
   同 (kind, version) 是 failed 或 installing 残留 → 删除目录与记录后重装
2. 写入 system_software：state=installing, progress=0
3. 下载到 cache\<kind>-<version>.zip.part
     响应码非 200 → DOWNLOAD_FAILED（带状态码），绝不当作成功
     每约 500ms 发一次 task:progress（0 到 70）
     可取消（context）
4. 校验：必须有 sha256 并比对，缺失或不一致 → DOWNLOAD_FAILED
   （MySQL、Redis 没有校验文件，这两种软件不校验，是软件本身的属性，不是跳过）
5. 解压到 software\<kind>\<version>.tmp，progress 70 到 90
     防 zip-slip：解出路径必须落在目标目录内，否则整个安装失败
     压缩包只有一个顶层目录时去掉这一层
6. 校验入口文件存在，否则 INSTALL_FAILED
7. 按类型后处理（6.5）
8. 目录改名为正式名，更新记录：state=installed, progress=100
     该 kind 还没有 main 版本 → 本版本置 main=1
     守护进程 → 分配端口（6.6）
     PHP / Node → 把 software 为 NULL 的同类型站点绑定到本版本
9. 删除下载包，发 task:completed
失败或取消：删除 .part、.tmp 目录，记录标 failed + error，发 task:completed 带错误
```

同一时间同一个 `(kind, version)` 只允许一个安装任务，取消靠内存里的 `map[key]cancel`，应用重启后残留的 `installing` 记录在启动时统一标为 `failed`（原因"安装被中断"）并清理半成品目录。

### 6.5 后处理

| 软件 | 后处理 |
|------|--------|
| PHP | 由 `php.ini-development` 生成 `php.ini`：`extension_dir` 写成**绝对路径**，启用 `curl` `fileinfo` `gd` `mbstring` `mysqli` `openssl` `pdo_mysql` `pdo_sqlite` `sqlite3` `zip`；时区设为 `Asia/Shanghai` |
| Node.js | 无 |
| Redis | 解压后在目录中查找 `redis-server.exe`，找不到则安装失败。社区构建的目录结构我没有实际解压核对过，实现时以实际为准 |
| MySQL | 不在安装时初始化，首次启动时执行 `mysqld --initialize-insecure --datadir=<dbdata>`，root 无密码，仅监听 `127.0.0.1` |

### 6.6 守护进程（MySQL、Redis）

装完即出现在软件商店「已安装」页签的版本行里，直接有【启动】【停止】和端口，没有"创建服务"。

- 端口：安装时从该 `kind` 的起始端口（MySQL 3306、Redis 6379）开始，取第一个未被其他版本占用、系统上也空闲的端口写入 `port`，之后固定不变。同一软件多个版本可以同时运行，各用各的端口。启动时端口被占用就报错，不再换端口。
- 启动前检查端口，被占用返回 `PORT_ALREADY_IN_USE`。
- 启动后等待端口监听，最多 30 秒；超时则杀掉进程并返回失败，附最后 20 行日志。
- 进程意外退出时发 `service:status-changed`，带最后几行输出，界面直接展示原因。
- 日志写入 `logs\software\<kind>-<version>.log`，界面读取尾部。
- 随应用启动：`autostart=1` 的守护进程在应用启动时拉起。

### 6.7 默认版本、站点版本、卸载

- **默认版本**（`main=1`）：每个 `kind` 一个，只在**创建站点时**取用，写入站点的 `software`。
- **站点版本**：站点的 `software`，创建时确定，之后只能在站点详情里手动改。
- **卸载**拒绝的情形（都给出具体站点名或进程）：
  - 守护进程正在运行 → `SERVICE_RUNNING`
  - 有站点的 `software` 指向该版本 → `RUNTIME_IN_USE`，列出站点名，由用户先去改站点版本
  - 该版本是默认且还有别的版本 → 把版本号最高的另一个版本设为默认
  - 该版本是默认且是最后一个 → 允许卸载（此时已无站点绑定它）

| 软件 | 页签与内容 |
|------|------------|

| Node.js | **概览**：安装路径、设为默认。Node 没有常驻配置，只有这一页 |
| MySQL | **概览**：状态、启停、端口、随应用启动、数据目录【打开】。**常用配置**：`max_connections` `innodb_buffer_pool_size` `character-set-server`。**配置文件**：`my.ini` 全文编辑。**日志**：运行输出 |
| Redis | **概览**：状态、启停、端口、随应用启动。**常用配置**：`maxmemory` `requirepass` `appendonly`。**配置文件**：`redis.conf` 全文编辑。**日志** |

配置存储原则：

- **配置只存在软件自己的配置文件里**（`php.ini`、`my.ini`、`redis.conf`），数据库不重复存一份，避免两处不一致。数据库里只保留端口、随应用启动、默认版本这类 DevEnv 自己要用的字段。
- 常用配置是对配置文件的"读取并改写单行"，保留其余内容与注释。全文编辑是直接读写整个文件。
- 保存前先把原文件备份为 `<文件名>.bak`。写入失败如实报错，不假装成功。
- 保存后提示是否生效：PHP 每个请求都重新读 `php.ini`，立即生效；MySQL、Redis 需要重启，保存结果里 `restart` 为 true，抽屉显示【保存并重启】。
- MySQL 的 `my.ini` 与 Redis 的 `redis.conf` 在首次启动前由 DevEnv 生成（带上端口、数据目录、仅监听 `127.0.0.1`）。保存前能否做语法校验取决于各自命令行是否提供，实现时核实，没有就不做假校验。
- 不做 MySQL root 密码修改、用户管理、数据库管理，这些是数据库客户端的工作。

### 7.2 关键端口

```go
type Gateway interface {
    Start(port int) error
    Stop() error
    SetRoutes(routes []Route)            // 整体替换，线程安全
    Port() int
}

type Route struct {
    ID    int64
    Hosts []string
    Kind  string
    Path  string   // 运行目录绝对路径（root 拼上 run），即文档根
    PHP   string   // php-cgi 所在目录，空表示未安装
    Port  int      // Node 端口
    Log   string   // 访问日志
}

type Runner interface {                 // 真实进程，不造假
    Start(key string, options Options) (pid int, err error)
    Stop(key string) error
    Status(key string) Status           // 运行与否 + PID + 退出原因
    Tail(key string, limit int) []string
}

type Catalog interface {
    Versions(ctx, kind) ([]Version, error)  // 带缓存；失败返回错误，不兜底
}

type Installer interface {
    Install(ctx, request Request, report func(progress int, message string)) error
}
```

`Result` 统一为 `{ok, message}`，`restart` 只在 `SaveConfig` 的返回里额外出现。

**SystemAPI**：`Settings()` `SaveSettings(in)` `PickFolder(title)` `OpenURL(url)` `OpenFolder(path)` `DataFolder()`。`Settings` 返回 `{theme, root, port, hosts, listening, error}`，其中 `listening` 表示网关是否在监听，`error` 是网关启动失败的原因（端口被占等），没有错误则为空。

### 7.4 事件

沿用标准事件名：

| 事件 | 载荷 | 触发 |
|------|------|------|
| `task:progress` | `{kind, version, progress, message}` | 安装中 |
| `task:completed` | `{kind, version, ok, error}` | 安装结束、失败或取消 |
| `service:status-changed` | `{id, running, pid, message}` | 守护进程启停、意外退出 |
| `site:status-changed` | `{id, state, message}` | 站点启停、Node 进程退出 |

### 7.5 错误码

沿用现有集合，`PHP_VERSION_IN_USE` 泛化为 `RUNTIME_IN_USE`，新增 `DATABASE_SCHEMA_MISMATCH`、`MIGRATION_FAILED`（迁移设计文档已定义）。`SERVICE_RUNNING`、`PORT_ALREADY_IN_USE`、`RUNTIME_NOT_INSTALLED`、`DOWNLOAD_FAILED`、`INSTALL_FAILED` 已存在。

## 十二、已知限制与取舍

| 项 | 说明 |
|----|------|
| PHP 每请求一个进程 | 比 FastCGI 常驻慢，没有 opcache 共享。FastCGI 客户端需要引入第三方库或自己实现协议，复杂度高。本地开发可接受，以后若慢再换 |
| 单网关端口 | 所有站点共用，靠域名区分；不同站点不能各用 80 以外的各自端口 |
| 仅 HTTP | 没有 HTTPS |
| 仅回环地址 | 局域网其他设备访问不到 |
| 仅 Windows x64 | |
| PHP 仅 NTS | |
| Node 站点端口约定 | 程序必须读 `PORT` 环境变量或在命令里用 `%PORT%`，写死端口的程序需要手动改 |
| MySQL 无断点续传 | 约 260MB，失败只能重来 |
| 网络依赖 | 版本清单与下载依赖外网，GitHub 有限流 |

## 十三、决策记录

下面是我替你做的取舍，不同意可以推翻：

1. **用内置网关，不用真实 Nginx。** 理由：装完即用、不需要生成和重载配置、没有 Windows 下 nginx 与 php-cgi 的进程管理问题。代价是没有 Nginx 配置可编辑，也没有 HTTPS。
2. **砍掉 Git、SSL、配置编辑、任务页。**
3. **默认域名用 `*.localhost`**，避免改 hosts。
4. **软件目录固定在 `%LOCALAPPDATA%\DevEnv`**，不可配置，避免迁移与相对路径问题。
5. **站点根目录默认 `%USERPROFILE%\DevEnv\www`**，可在设置里改。
6. **站点不存运行状态**，状态由网关与进程管理器实时给出。
7. **删除站点永不删除项目目录。**
8. **删除三份被取代的旧设计文档。**
9. **根目录与运行目录分开**，运行目录就是网关的文档根，由用户在创建时选择，默认自动识别。
10. **软件配置只写进软件自己的配置文件**，数据库不存第二份。
11. **左侧导航只剩仪表盘、网站、软件商店、设置**，旧数据全部清空且不迁移。
12. **开发模式不向下兼容**，直接用最新写法，见 2.1。
13. **不做保底**：不写三元 / `||` / `??` 补默认值，不设离线内置列表、不自动换端口、不"找不到就回退默认版本"，见 2.1。
14. **命名尽量短，但完整单词不缩写**：变量一个完整单词，方法 `xxxXxx`，只保留 `id` `pid` `url` `ok` `ctx` 和 Go 局部的 `err` 这几个惯用缩写，字段与接口已按此统一，见 2.1。
15. **站点版本在创建时确定**，不再"跟随默认"，这是第 13 条的直接结果。
