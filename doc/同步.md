# 手动同步与微信上传

## 操作原则

所有发布都由用户主动点击：保存配置 → 检查环境 → 生成预览 → 核对目标和文件 → 确认手动发布。项目启动、文件变化、Git 提交、DevEnv 启动均不触发发布，也没有定时同步、自动重试或自动恢复上传。

预览绑定当前项目、配置和文件摘要，有效期 15 分钟且只能使用一次。任务开始前重新校验并复制到独立的过滤后快照；文件变化则拒绝上传，要求重新预览。

## PHP / Node.js：服务器同步

入口：项目详情 → 服务器同步。

1. 发布源目录填写相对项目根目录的路径。PHP 源码通常填写 `.`；Node.js 可填写源码目录或构建产物目录。需要构建时，先在本地完成构建。
2. 填写 SSH 主机、端口、用户名、服务器项目绝对目录（例如 `/var/www/my-project`）。目标根目录必须提前创建，建议使用仅对该目录有写权限的部署账号。
3. 填写通过管理员等可信渠道核验的 `SHA256:...` 主机密钥指纹。可由服务器管理员使用 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 核对。不要把连接错误中显示的未知指纹直接当作可信值。
4. 使用本机 SSH 私钥文件；加密私钥在操作前填写口令。也可以不选私钥，使用本次连接密码。密码、口令和私钥内容不保存到数据库；测试或提交任务后界面会清空密码和口令。
5. 保存配置、检查连接、生成发布预览，确认后开始上传。

传输使用 SSH/SFTP；只新增或覆盖预览中的文件，不删除服务器额外文件。每个文件先上传到同目录临时文件，再用 POSIX rename 原子替换；服务器须支持该 SFTP 扩展。服务器目标及其父目录不得是符号链接。现有文件权限保留，新文件权限为 `0644`。

这是文件同步，不是数据库同步或远程运维：不读取数据库服务、不安装依赖、不运行 Composer/npm 命令、不重启 Node.js、不修改 Nginx。PHP 的 `vendor` 默认可上传；Node.js 的 `node_modules` 不上传，需要在服务器维护生产依赖，或发布已准备好的独立构建产物。

整批发布不是事务：中断时可能已有部分文件更新，不自动回滚。发布前请做好服务器备份，并选择合适的维护窗口；不能将其视为零停机部署。

## 小程序：微信发布

入口：小程序项目详情 → 微信发布。

1. 对 uni-app / Taro 项目先生成微信构建产物。项目根目录填写源码目录（例如 `G:\2026\code\dapai\uni`），发布源目录自动使用 `dist/dev/mp-weixin`，实际上传的就是该编译目录，不上传 uni 源码。若使用其他构建模式，可手动修改为对应的 `dist/*/mp-weixin` 目录；原生小程序可填写 `.`。
2. 在 AppID 输入框中逐个填写小程序 AppID，按 Enter 添加为标签，可绑定多个 AppID；发布时会逐个上传到对应的小程序后台。构建目录中的 `project.config.json` 必须存在，发布时会在上传快照中临时替换 `appid`，不会修改本地编译目录。项目配置中的资源根目录必须位于发布源目录内，不能指向项目外。
3. 在“全局设置”中填写微信开发者工具 CLI 路径，通常是 Windows 安装目录下的 `cli.bat`。所有小程序项目共用此配置，路径必须指向本机已安装的真实文件，不自动下载或安装工具。
4. 在微信开发者工具“设置 → 安全设置”中开启服务端口，并登录具有该 AppID 上传权限的账号。DevEnv 的环境检查只调用 CLI 帮助命令，不会上传代码。
5. 填写上传版本、说明和机器人编号。保存后检查本地工具、生成预览并手动确认上传。

发布时调用微信开发者工具 CLI 的 `upload --project <目录> --version <版本> --desc <说明> --robot <编号>` 命令，项目配置由 CLI 读取。上传目标是微信后台开发版本，不包含自动提审和正式上线；请打开微信后台核对版本，再手动完成审核与发布。网络中断或取消后结果可能未确认，务必到微信后台检查，不自动重传。

CLI 参考：[wechat-devtool CLI](https://github.com/NewFuture/wechat-devtool)。

## 排除规则与安全边界

- 始终排除 Git/SVN/Hg 目录、`.env*`、`.ssh`、常见包管理凭据文件、`node_modules`、常见私钥/证书文件、数据库文件及 SQL 导出。配置中明确指定的私钥文件也排除。
- 服务器同步额外保护 `storage`、`runtime`、`logs`、`uploads` 和日志文件。服务器中的环境变量、用户上传数据应独立维护。
- 服务器同步可增加排除规则，每行一条，支持 `tests/`、`public/cache/`、`*.map` 等目录、相对路径和单层通配；小程序微信发布不提供额外排除规则，直接上传编译产物；不支持 `**`、绝对路径或 `..`，不可取消内置保护。
- 排除按文件名/路径进行，不进行源码敏感内容扫描。其他名称的密码配置、压缩备份等需自行加入排除规则并检查预览。若发布依赖 SQL 迁移文件，需单独采用数据库迁移流程，本功能不上传这些文件。
- 预览是本地待上传清单，不是服务器差异对比；每次同步都会上传全部符合规则的文件。
- 拒绝目录穿越和符号链接；任务运行时禁止修改配置和重复启动，同一发布目标不能并发上传。

## 存储与生命周期

- 新增编号迁移 `000006_project_deployment.sql`，不修改已执行迁移，不清空现有数据库。
- `system_project_deployment` 保存非秘密配置及密钥文件路径；`system_project_deployment_log` 保存结果、目标、完成文件数和时间。界面显示最近 20 条。
- 长任务后台运行，开始立即返回；仅任务运行期间轮询进度，支持取消。切换页签不停止任务，退出 DevEnv 会请求取消；下次启动只标记未完成任务为中断，不恢复执行。
- 发布适配器通过 `ports.DeploymentProvider` 注入，项目模板通过 `server-sync` / `wechat-upload` 能力控制入口，后续扩展发布方式不修改项目基础表。

## 验证范围

测试使用临时数据库、本地内存 SFTP 测试服务器和模拟的微信开发者工具 CLI，覆盖手动触发、预览失效、禁止并发、取消、敏感文件排除、快照校验、指纹验证、保留远端额外文件及微信参数。真实服务器和微信账号仍需用户配置后进行联调。
